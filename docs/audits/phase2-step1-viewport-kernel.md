# 第二阶段第一步：视口内核

日期：2026-11-09

这一步只替换无限画布的坐标、缩放、平移和基础节点落位。拖拽连线、撤销、保存读取、模型调度、素材管理都还在旧文件里。CainFlow、商品分析、SKU、批量生成、电商工作台、`LICENSE` 和版权声明都没有动。

交付当时默认走旧实现，要用户显式打开。下面的开关表是当时的记录，不是现在的操作方法。查询参数、`localStorage` 和 `setActive(false)` 已经去掉，运行时只走新内核，见 `docs/audits/kernel-defaults-next.md`。旧文件没有删除。

## 来源与做法

规格来自当前小美画布已经在用的相机模型，而不是把大熊函数逐行改写进新文件：

- 相机记录仍是旧 JSON 里的 `viewport: { x, y, scale }`。`x/y` 是世界原点在视口里的屏幕平移，`scale` 是缩放。
- 屏幕点换世界点：`(指针在视口内的位置 - 平移) / 缩放`。
- 世界层用 CSS 变换画出这个相机。经典画布是 `translate3d`，智能画布是 `translate`，后面都乘 `scale`。节点自己的 `x/y` 不随缩放改写。
- 滚轮缩放保持光标下的世界点不动。经典画布每格乘 `0.92` 或 `1.08`。智能画布按滚轮像素做最多 15% 的一步。
- 适配全部节点、空白画布默认缩放 `0.45`、内容过散时改看最近节点，这些阈值与现网一致，写在调用参数里。
- 小地图把节点包围盒和当前视野投到右下角。节点卡片的 `left/top` 仍等于节点的 `x/y`。

新文件是 `static/js/xiaomei-viewport-kernel.js`。它用自己的函数划分（相机读写、围绕锚点缩放、包围盒适配、小地图投影、屏幕矩阵求逆），不从 `canvas.js` 或 `smart-canvas.js` 裁剪。对照 `hero8152/Infinite-Canvas` 的 `canvas.js` 与 `smart-canvas.js`，新文件没有连续 8 行相同的规范化代码；最长相同行分别是 3 行和 2 行，属于 `return` 一类短句。

`node --test tests/xiaomei-viewport-kernel.test.cjs` 锁定上述数值：默认关闭、查询参数、光标锚点缩放、拖拽平移、滚轮增益、适配与聚焦、小地图包围、节点坐标字符串、仿射求逆。

## 开关与回滚

| 操作 | 结果 |
| --- | --- |
| 什么都不做 | `XiaomeiViewportKernel.isActive()` 为假，旧函数整段执行 |
| 打开 `canvas.html` 或 `smart-canvas.html` 时加上 `?xmViewport=1`（也接受 `next`） | 写入 `localStorage['xiaomei.viewportKernel']='next'`，之后同一站点的画布都走新内核 |
| 加上 `?xmViewport=0`（也接受 `legacy`） | 写回 `legacy`，立刻回到旧实现 |
| 控制台 `XiaomeiViewportKernel.setActive(false)` 后刷新 | 同上 |

页面根节点会带 `data-xm-viewport="legacy"` 或 `next`，用来确认当前路径。旧脚本文件没有删除。关掉开关后，平移、缩放和节点位置重新由原来的函数计算。

主壳如果用 iframe 打开画布，要在画布页地址上带查询参数，或在同一站点先设好 `localStorage` 再刷新画布帧。

## 最小适配层

旧文件不能从外部改到 `let viewport`，所以在经典画布和智能画布里加了运行时分支：开关关闭时走原来的语句，打开时把同一件事交给内核。分支只包住视口、小地图投影和节点原点，不改连线、撤销或保存。

触及的旧文件：

- `static/js/canvas.js`：`screenToWorld`、`applyViewport` 的变换字符串、滚轮、空白处平移、按钮缩放、适应全部、视口居中、缩放预览退出、小地图、`renderNode` 的 `left/top`。
- `static/js/smart-canvas.js`：同一组相机操作，另加滚轮累积、屏幕矩阵换算、内容聚焦、节点模板的 `left/top`，以及拖拽结束和分组缩放时写回原点。
- `static/canvas.html`、`static/smart-canvas.html`：在画布脚本之前加载内核，并给画布脚本加了缓存参数。

智能画布在开关打开时，屏幕换算改走内核的矩阵求逆。求逆用行列式，不用原来的 `DOMPoint` 分支。世界层还没布局好时，回退尺寸是 6000×4000，与当前画布元素的缺省布局一致。`applyViewport` 里工具条、提示词浮层、协作光标仍调用原来的后续语句，避免这一步把那些交互重写掉。

## 手工验收

1. 不带参数打开经典画布和智能画布。确认 `document.documentElement.dataset.xmViewport === 'legacy'`。平移、滚轮缩放、节点位置应与改动前一致。
2. 地址加上 `?xmViewport=1` 并刷新。属性变为 `next`。
3. 平移：按住空白处拖动画布，松手后节点仍在拖动前的世界坐标。
4. 缩放：滚轮以光标为中心放大缩小；工具栏百分比跟着变。智能画布的缩放滑杆仍以中心为锚点。
5. 节点：旧项目打开后，节点 `x/y` 与卡片 `left/top` 一致，连线仍由旧代码绘制，端点不需要这一步重写。
6. 小地图：节点块和视野框仍在，点击小地图会把对应世界点移到视口中心。
7. 回滚：改成 `?xmViewport=0` 再刷新，属性回到 `legacy`，上述操作重新走旧函数。
8. 相机节点、商品分析、SKU、批量入口仍在，本步没有改它们的文件。

本环境跑了内核单测和 `node --check`。无界面 Chrome 在这台机器上没有正常退出，所以没有完成真实页面的点击验收。上面的手工步骤需要在装有现成数据的小美画布里再走一遍。
