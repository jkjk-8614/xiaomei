# 第二阶段第二步：拖拽、连线与分组

日期：2026-11-09

这一步只替换节点拖拽、连线几何和分组关系。撤销重做、保存读取、模型调度和素材管理仍在旧函数里。CainFlow、商品分析、SKU、批量生成、电商工作台、`LICENSE` 和版权声明都没有改。

交付当时默认走旧实现，要显式打开。当前默认已改为 next，回滚方式见 `docs/audits/kernel-defaults-next.md`。旧文件没有删除。

## 来源与做法

规格来自当前画布已经在用的交互，不从大熊函数逐行改写：

- 拖拽位移是屏幕增量除以当前缩放。智能画布可选按 28 像素网格吸附。未超过 4 像素的按下仍不算拖动。
- 拖动分组时，组成员一起走。多选时，其余选中节点和它们的组成员一起走。智能画布还会把所在分组整组纳入。
- 经典连线是水平贝塞尔，弯曲至少 80，或横向距离的 0.45 倍。智能画布平时用同类曲线（下限 50），拖动中改成直线，历史连线改为纵向弯曲。
- 没有端口元素时，连线落在节点左缘或右缘的中点。松手时 48 像素内的最近端口可以接上。
- 经典连线规则：生成节点可以连到输出；媒体生成节点可以连到另一个生成节点，但不能成环；循环、LLM 和普通输入按节点类型允许。
- 图片或提示词的中心落入分组矩形时加入该组，离开时移除。按连线深度把节点排成列。

新文件是 `static/js/xiaomei-node-kernel.js`。对照上游 `canvas.js` 与 `smart-canvas.js`，没有连续 8 行相同的规范化代码，最长相同行是 3 行和 2 行。

`node --test tests/xiaomei-node-kernel.test.cjs` 覆盖开关、拖拽队列、分组展开、曲线端点、连线规则、列布局和边去重。

## 开关与回滚

这个开关和第一步的视口开关分开。

| 操作 | 结果 |
| --- | --- |
| 什么都不做 | `data-xm-nodes="legacy"`，拖拽、连线、分组仍由旧函数计算 |
| `?xmNodes=1` 或 `next` | 写入 `localStorage['xiaomei.nodeKernel']='next'` |
| `?xmNodes=0` 或 `legacy` | 写回旧实现 |
| `XiaomeiNodeKernel.setActive(false)` 后刷新 | 同上 |

视口仍用 `?xmViewport=1`。两个开关可以单独打开。

## 最小适配层

旧脚本里的手势、撤销入栈、协作锁、菜单和保存调用都留着。开关打开时，只把数值计算交给内核：

- `static/js/canvas.js`：拖拽同伴、位移、贝塞尔、端口兜底、最近端口、成环判断、连线是否允许、分组包含、按连线排版、分组成员平移取整。
- `static/js/smart-canvas.js`：拖拽位移和吸附、分组展开、连线曲线、拖线预览、成员列表、连线去重、按连线排版、分组成员平移取整。
- `static/canvas.html`、`static/smart-canvas.html`：在视口内核之后加载本内核，并更新画布脚本缓存参数。

## 手工验收

1. 不带参数打开经典画布和智能画布。`document.documentElement.dataset.xmNodes` 为 `legacy`。拖节点、拉线、分组与现在一致。
2. 地址加上 `?xmNodes=1` 并刷新。属性变为 `next`。
3. 拖动单个节点、分组和多选。组成员应跟着移动。智能画布打开吸附时，位置落在 28 像素网格上。
4. 从一个端口拖到另一个端口。能接上的类型仍能接上，自己连自己和成环仍然拒绝。曲线形状与旧实现一致；拖动节点时智能画布的线暂时变直。
5. 把图片或提示词拖进分组，松手后成为成员；拖出后离开。打开旧项目时，已有 `items` 和 `connections` 仍然可读。
6. 改成 `?xmNodes=0` 刷新，确认回到旧实现。
7. 相机节点、商品分析、SKU、批量入口仍可打开。

本环境完成了单测和语法检查，没有在桌面壳里用真实旧项目点击。请在本机按上面的步骤再看一遍。
