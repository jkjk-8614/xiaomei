# 扩图与 AI 分层检查记录

本次检查对象为小美画布新增扩图交互、`canvas_image_layers.py` 分层链路及共享 PSD 导出。参考依据为本机 CanvasForge 安装包静态分析及用户提供的界面截图。检查没有调用真实付费模型，也没有在 Photoshop 内打开导出文件。

结论：主要交互与任务链路已经实现，但尚不能称为与 CanvasForge 完整等效。此前的模拟测试只覆盖了主要路径；本次针对异常输入、异步状态及结果一致性补测，并修复了以下问题。

## 已修复问题

| 优先级 | 原问题及影响 | 修复 |
|---|---|---|
| P1 | 大尺寸原图选择 1K/2K 扩图，输出宽高仍被原图尺寸托底，造成预览与结果画幅、留白不一致 | 图片与外框按同一比例缩放；增加大图降分辨率和尺寸上限测试 |
| P1 | 底图上传期间关闭编辑器或更改图片，异步返回后可能修改错误状态 | 提交时记录编辑状态，返回后重新核对；改变状态时停止后续提交 |
| P1 | 不同比例的生成图层被非等比拉伸，商品形状可能变形 | 等比放置，记录比例差异并标记复核；同步 PSD 智能对象定位 |
| P1 | 检查结果有差异但 pass=true 时可能显示通过；空锚点未标记，异常 matches 可导致恢复反复失败 | 严格检查响应格式，有差异不能通过；检查锚点数量、范围、间距和拟合残差；不可靠定位标记复核 |
| P1 | 同名合成文件被覆盖，导出期间另一请求重试可能造成新旧图层混用 | 图层/合成结果使用独立版本文件，导出固定任务快照，服务端校验版本，拒绝过期上传 |
| P1 | 页面关闭期间完成的任务，刷新只恢复运行中任务，最终图层可能缺失 | 来源节点保存任务关联；恢复已关联的完成、失败及暂停任务，不重新提交模型 |
| P2 | 单层重试只重复原提示词，未利用上次失败信息 | 将透明度、定位及内容差异加入纠错提示词 |
| P2 | 同节点多张图片共享分层记录和待确认请求 | 按来源图片隔离历史和待确认请求；历史原图使用任务快照 |
| P2 | 重试期间旧图层/旧合成仍显示为当前结果 | 清空对应节点的过期显示，显示等待更新或尚未检查 |
| P2 | 删除生成历史可能使后续恢复失去分层原始文件 | 任务目录独立保存来源和每次生成的图层副本 |
| P2 | 超出导出工作量的自定义任务先调用分析才失败；部分初始化状态可能缺少尺寸 | 自定义任务提前检查工作量；规划与尺寸计算全部通过后再保存图层状态 |
| P2 | 同一请求编号更换参数会静默返回旧任务 | 校验请求参数一致性，不匹配时明确报错；前端清理明确失败的请求编号 |
| P2 | 查询无超时可能卡住后续轮询；PSD 验证只比较对象数量 | 查询增加超时，保留原任务查询；PSD 增加嵌入内容逐字节读回检查 |
| P2 | 固定比例拖动时，非拖动方向的中心约束不完整 | 补齐偏心原图场景的边界与中心约束测试 |
| P1 | 元素归属仅靠提示词，重复分配和漏分配仍可能开始生图 | 增加元素清单、独占归属和完整覆盖校验，生成与复核均携带元素清单 |
| P1 | 检查失败必须手动重做，缺少有预算的纠错链路 | 增加每层 0–2 次自动纠错；只重做内容或透明度检查失败的层，持久化次数、反馈与尝试编号，重启不重置预算 |
| P1 | 本地任务失败或即梦排队后，只查本地状态无法取回后来完成的图片 | 优先恢复原响应回执、查询原上游任务或续查即梦 submit_id；失败和状态不明均不会触发自动重新提交 |
| P2 | 图层串行处理较慢，直接增加并发又可能遗留未收尾的后台任务 | 可选 1–3 层并发；发生错误后不再派发新层，等待已启动的工作结束并保存编号后再允许恢复 |
| P2 | PSD 同步压缩与读回阻塞页面，原生位图资源释放不及时 | 转移像素缓冲区到 Web Worker，完成后终止 Worker；保留独立图层和智能对象逐字节验证 |
| P1 | 分层请求失联后修改参数或打开其他历史，可能用同一编号提交不同参数 | 未确认请求保留完整参数并锁定选项，重开面板继续原请求；优先恢复对应编号的记录 |
| P1 | 普通 PS 图片回传会把 PSD 置入为整体智能对象，无法直接看到全部图层 | 增加 PSD 新文档打开模式、插件能力检查、指定接收面板和发送去重；普通图片保持置入模式 |
| P1 | UXP 导入错误回执为 error，后端可能将它记录为 done | 插件明确发送 failed；后端兼容旧 error 状态及带错误信息的回执，画布显示实际确认结果 |

补齐操作：扩图范围重置、Enter 提交，以及打开编辑器时恢复所选节点质量参数。继续和单层重试沿用原任务模型，面板说明了此行为；修改选项只作用于新建/重新分层。

## 与参考软件的差距及未验收项

| 项目 | 当前状态 | 影响 |
|---|---|---|
| 扩图交互 | 四边、四角、原图移动、比例、Alt 对称、质量/数量/模型、重置和提交具备 | 保留小美画布自身编辑器布局，非逐像素 UI 复刻；接缝效果未用真实模型验证 |
| 分层规划 | 层名、类型、框、提示词、元素清单与独占归属均有结构化校验 | 代码能保证清单内不重复/漏分配，但模型是否识别出原图全部元素仍需视觉复核 |
| 模型能力 | 复用已配置平台及通用生成适配器 | 动态模型列表不等于每个模型都支持视觉/透明输出；当前适配器只对明确支持的模型发送透明参数，不能保证截图中的全部模型等效工作 |
| 分层执行 | 可选 1–3 层并发；停止、恢复、显式单层重试和有次数上限的自动纠错具备 | 自动纠错仅针对内容或 Alpha 检查失败；低分辨率、定位不可靠及仅在最终合成发现的差异保留复核，不盲目重做全部图层 |
| 上游状态同步 | 复用平台查询、原响应恢复与即梦排队续查；保留原编号 | 受现有平台适配器和有效回执限制，尚未验证每家供应商真实断线后的恢复行为 |
| 语义及合成检查 | 分层内容检查、锚点定位、Alpha 检查及最终复核具备 | 检查也依赖模型判断，不能保证复杂文字、Logo、透明材质、遮挡及主体身份准确 |
| PSD | 独立图层、名称、位置、透明度、原图对照、嵌入智能对象、读回验证及桥接新文档打开具备 | 需更新 Photoshop 内加载的 UXP/CEP 插件；尚未在 Photoshop 中实机验收，模拟插件回执不等于实机兼容性验证 |
| 4K 多图层 | 有工作量限制、模型实际尺寸提示和后台打包；4K 四层加对照层的导出测试通过 | 测试未测量进程峰值内存，也未覆盖最大层数及高噪声图片；选 4K 不代表模型返回原生 4K |

优先后续验收：使用实际平台分别验证扩图与两层分解，核对透明通道和商品细节；在 Photoshop 中打开、隐藏/移动图层和编辑智能对象；随后测试复杂海报及 4K 多图层。验证通过前不应称为完整复刻或生产效果验收完成。

## 验证证据

- `tests/test_image_layers.py`：23 项通过。模拟模型，覆盖规划、检查、定位、失败恢复、停止、单层重试、原图副本、版本隔离与请求幂等；新增归属冲突、并发收尾与数量限制、自动纠错及重启预算、上游状态查询、原始回执恢复和即梦续查。
- `tests/outpaint-geometry.test.cjs`：4 项通过。四角/四边、Alt、固定比例与偏心原图，以及大图选择低分辨率。
- `tests/image-layers.browser.cjs`：通过。真实 Edge 无头浏览器，模型响应为测试桩；覆盖面板、历史隔离、节点连线、刷新恢复、上传后取消、扩图原图保护、智能对象 PSD 读回和旧 ComfyUI 导出数据结构。
- `tests/canvas-background-removal.browser.cjs`：通过，确认现有画布去背景流程未回归。
- `tests/image-layers-psd-stress.browser.cjs`：通过。Edge 无头浏览器，4096×2304、4 个生成图层与隐藏原图，导出 11,196,649 字节，单独运行约 1.26 秒，联合回归约 1.45 秒；打包 Worker 运行期间页面定时器继续执行。素材为本地生成的简单图形，不能代表所有真实图片的耗时或峰值内存。
- `tests/test_image_layers_photoshop.py`：6 项桥接隔离测试。覆盖旧/离线插件拒收、指定面板领取、发送幂等、普通图片兼容、无效 PSD、失败回执。
- `tests/image-layers-photoshop-plugin.cjs`：2 项插件模拟测试。覆盖 UXP 新文档打开及旧置入路径、打开失败回执和 CEP 已有文档时的 PSD 新文档打开。
- 浏览器测试另覆盖 Photoshop 发送与回执显示，以及未确认分层请求在重开面板后保持参数一致。
- Python 编译和相关 JavaScript 语法检查通过。
- `tests/image_layers_app_smoke.py`：在不读取用户配置的临时副本启动服务，首页、应用信息、平台、历史和分层列表五个接口均返回 200。

以上验证未消耗用户模型额度，不能作为真实模型输出质量或 Photoshop 兼容性通过的证据。
