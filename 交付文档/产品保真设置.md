# 产品保真设置

产品保真是画布中的独立图片处理节点：**产品图片 → 产品保真 → 绘画**。保真节点内编辑图片与保护规则，下游普通 API 绘画节点选择模型、填写提示词和生成图片。复用已有平台列表、模型适配、后台任务、历史和资源存储。新保真节点默认启用；普通节点未连接保真时保持原行为，保真配置不进入最近使用参数。

## 使用

1. 重启后端并刷新小美画布页面，在创建菜单选择「产品保真」，把产品图片连接到它的左侧输入口，再从右侧输出口连接普通绘画节点。普通绘画运行区的「连接产品保真」也可插入中间节点，保留原有图片与手动参考图的顺序。
2. 节点内左侧为图片处理区，右侧直接展开七个设置区块；顶部区块导航可以跳到对应位置，长内容在节点内滚动。设置随修改保存，无需打开对话框或再点保存。
3. 在「产品识别」的「保护哪张产品图」选择主图；主图身份独立于参考图位置，拖动下游参考图不会改变主图。移除主图后必须重新选择。产品类型、形状和真实尺寸由用户确认，当前不做语义自动识别。
4. 换背景选择「保留原产品像素 · 换背景」：使用透明产品 PNG，或上传与原图同尺寸的黑白蒙版（白色保护、黑色背景），或在左图用「画保护区」标记。手绘区域可用「擦除保护区」修改；上传蒙版需要先重置再重画。可先使用原有抠图工具处理副本。
5. 「结构约束」内的「细节保护」可选择只用原图、纹理图、局部图或组合。点击「寻找细节并预览」生成本地纹理与边缘候选；也可用左侧「框选细节」标出 LOGO、接缝等区域。手动框优先，自动候选补足数量上限，裁切保留原分辨率。删除一个自动候选时，剩余候选转为手动区域并关闭自动重选，避免下次又把它加回来。
6. 点击「更新处理结果」在左侧查看辅助图，可点击放大、另存。此步骤无需模型或平台，不调用付费 API。下游模型限制显示在节点底部，实际参考图与降级原因可在「高级模式」查看。
7. 在右侧绘画节点选择模型、填写场景提示词，使用原有运行按钮。运行时按最新保真配置和当前模型重新准备辅助图，生成后在中间节点的「校验规则」查看上次生成的检查报告和原图/结果对比。

七个区块依次为产品识别、结构约束、视角控制、生成强度、校验规则、失败重试、高级模式；细节保护是结构约束内的子模块。

自动选区用蓝色虚线显示，手动区域用橙色显示。自动选区不是语义识别，没有产品蒙版时可能包含背景；应先画蒙版或改用手动区域。原图纹理信息不足时不添加自动裁切，显示原因。新建产品保真节点默认允许自动裁切；旧配置缺少该字段时保持关闭。

结构模式可选择「可靠同视角对齐后恢复」，配合产品蒙版和已确认的平面几何，并调整本地恢复强度、羽化和对齐门槛。严格模式使用原像素合成，视角模式禁用旧图高频回填。高级模式的高反差增益只改变本地灰图，范围与参数由 `product_fidelity.py::normalize` 校验。

## 模式与限制

| 模式 | 实际执行 | 验收范围 |
|---|---|---|
| 严格保真 | 生成背景与环境，随后用本地产品蒙版确定性合成原图；输出采用原图画幅、位置和产品尺寸 | 检查完全不透明核心区域 RGB 像素差；边缘羽化、透明/反光融合、环境质量需人工检查 |
| 结构保真 | 原图和有序辅助参考生成；同视角平面特征匹配、可靠时本地细节恢复和实验外框检查 | 不把相似度当作 LOGO/OCR 正确；检测不足标记未能判断，不假判通过 |
| 视角保真 | 目标角度提示词、多视角用户参考，可附加平面透视示意图 | 不做旧视角高频回贴；不可见面为 AI 推测，不使用正面外接框比例判定新视角 |

严格保真不能与产品材质/光照变化、上游视角控制、扩图或放大同时执行。产品像素与背景光照的融合有边界：高度透明或反光产品需要手动复核。画幅比例与产品实体比例分别记录，用户填写的真实尺寸不会由图片推测补全。

结构约束通过普通参考图与提示词表达，不是模型原生控制权重。同视角恢复使用有界的特征匹配、RANSAC、覆盖区域、旋转与残差门槛；外框失败或对齐不足时跳过恢复。四角与边长检查为实验性启发式，不表示精确畸变率。

平面透视代理只适用于用户确认的平面矩形与左右/俯仰有限角度；根据真实宽高或参考图可见比例生成普通参考图，不重建隐藏面。盒体/3D 重建、产品自动识别、语义 ROI、OCR/部件语义检查、手动几何对齐和高级深度控制暂不可用。

自动重试保持禁用：现有渠道缺少可靠的单次费用与总额外消费估算。用户可查看错误后使用原有重试入口，重新生成会再次调用模型。查看已受理任务的结果只查询/合成本地结果，保留原任务的产品保护配置。

## 模型与请求

实际模型来自 `/api/providers` 与现有模型拉取接口。保真节点不会新建模型菜单或猜测代理别名对应的官方版本。

- OpenAI Images 使用现有有序 multipart 图片编辑路径，保留每个 GPT-Image 型号的尺寸、质量、背景规则。不发送 `input_fidelity`、ControlNet 或高频强度等不存在的参数。
- Google 使用现有 `generateContent` 的文本和有序图片内容块；按型号处理输出配置，不发送 OpenAI 的质量或二值 mask 参数。初代与 Lite 的分辨率限制分别处理；思考中间图片在所有最终解析路径中排除。
- 产品蒙版用于本地保护。即使主图在第二位，也不会为 OpenAI 首图 mask 规则偷偷调整用户排序。
- 辅助图附加在用户原图后。原图超预算会报错；预算不足时只减少派生图并显示原因。源图、手绘蒙版和 ROI 改变后重新生成对应缓存。
- 官方型号、渠道别名、应用参考图预算、输出配置、原生支持项与本地能力的唯一声明入口是 `product_fidelity.py::capabilities`；查询 `/api/product-fidelity/capabilities?provider_id=...&model=...` 获取当前值。

渠道只完成单次真实验收不代表全部质量、尺寸或最大输入预算已经验证。`channelVerified` 表示完整渠道能力是否已验证，单次成功回执不会把整个能力表提升为全部验证。

官方依据：[OpenAI 图片编辑接口](https://developers.openai.com/api/reference/python/resources/images/methods/edit)、[Google 图像生成文档](https://ai.google.dev/gemini-api/docs/image-generation)。真实渠道验收与官方直连能力分开记录，见对应日期的验收报告。

## 开发与数据

- `static/js/product-fidelity.js`：独立中间节点、稳定 reference ID、手绘蒙版、ROI、本地预览、连接与配置传递。
- `static/css/product-fidelity.css`：沿用画布的主题变量和语义字阶。
- `static/js/smart-canvas.js`：当前节点设置、运行请求与结果报告；`productFidelity` 不进入最近使用参数。
- `product_fidelity.py`：非破坏性图像处理、内容哈希缓存、参考排序、本地合成、保守对齐与实验几何检查。
- `main.py::build_online_image_result`：预处理→已有模型适配器→保存模型输出→本地保护→历史/后台任务。
- `main.py::protect_recovered_product_result`：恢复已付费上游任务时重新执行本地保护。

请求中的 `product_fidelity` 只控制本地策略；配置、参考图 URL/ID 以及结果报告随节点/任务保存，派生图片使用现有生成目录。不把大段 Base64 塞入节点 JSON。原图不被覆盖，中间图和模型原始输出可由现有存储清理机制管理。复制、导入导出与已有撤销快照保留配置；项目现有全局编辑器只有撤销机制，本功能没有宣称新增全局重做。

节点类型为 `smart-product-fidelity`，配置保存为 `fidelityConfig`。中间节点输出原始参考图并传递配置；辅助图由下游运行时的现有后端准备，避免把本地预览的派生图重复添加到生成请求。旧版带 `productFidelityNode` 标记的绘画节点自动迁移，保留已有图片和保护设置。下游绘画保存当次配置快照与来源节点 ID；断开或禁用中间节点后不再沿用其规则。一个绘画节点接入多个启用的保真来源会明确报错，不自动混合蒙版。

新增接口：

| 接口 | 用途 |
|---|---|
| `GET /api/product-fidelity/capabilities` | 查询所选模型/渠道的实际适配能力 |
| `POST /api/product-fidelity/preview` | 接受图片请求与保真配置，仅生成本地中间图和参考顺序；`local_only: true` 无需平台或模型，实际生成时重新匹配下游能力 |

OpenCV 用于可选的阶段 2 对齐和几何检测。缺少时严格合成、高反差和 ROI 仍可运行，自动恢复显示不可用；不自动安装大型模型或启动 ComfyUI。

## 验证

```powershell
.\python\python.exe -m py_compile main.py product_fidelity.py
.\python\python.exe -m unittest discover -s tests -t . -p test_product_fidelity.py
.\python\python.exe tests/product_fidelity_app_smoke.py
node --test tests/product-fidelity.browser.cjs
```

单元、浏览器与接口集成测试均使用临时目录/模拟接口，不读取用户图片或调用付费模型。`tests/product_fidelity_live.py` 是另行显式运行的真实验收程序，要求 `--execute-paid-calls`，每个选中型号只提交一次，不自动重试，报告不导出凭证或原始上游响应。
