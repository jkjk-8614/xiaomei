# 验收与故障排查

## 1. 基础启动

| 检查 | 预期 |
|---|---|
| `python main.py` | 监听 3000，无导入错误 |
| `/` | 返回小美画布主界面 |
| `/api/app-info` | 返回版本/项目资料 |
| `/api/providers` | 返回平台数组 |
| `/api/history` | 返回数组，空历史也不报错 |
| `/api/assets` | 返回统一素材索引；空索引也不报错 |

## 2. API 设置

- 地址验证不会无限转圈。
- Key 显示掩码，不回显完整值。
- 拉取模型后按图片/对话/视频分类。
- 在线生图下拉框立即同步变化。
- API 设置中的通用平台可把两个不同账号的 Key 分别保存为记录；下拉切换后新 Key 立即成为当前运行 Key，删除当前记录后不会删除其他记录。旧版单 Key 配置首次打开时应自动显示为“账号 1”，且界面、日志和 `data/api_key_profiles.json` 都不出现完整 Key。
- 保留即梦 CLI、GPT/Codex CLI、Gemini/Antigravity CLI 支持；三个 CLI 在各自 API 设置面板均提供“安装 / 更新”和“检查更新”，安装任务显示状态与日志路径。
- 推荐 API/平台引导中的“获取 Key/Token”在桌面端使用系统默认浏览器打开，不创建 Electron 应用内网页子窗口；普通浏览器按新标签打开。

## 3. 生图

- 选哪个模型就提交哪个模型，历史记录模型名一致。
- 小美画布图片生成固定使用异步任务；其他生图入口按各自已有模式设置运行。
- 进度卡显示任务状态与耗时；在线 API 仅在返回真实进度时显示百分比，本地 ComfyUI 的估算值明确标注为预计进度。
- 失败卡不消失，有错误信息。
- 四张结果完整显示四张。
- GPT Image 2.5 选择 `xhigh`/`max` 质量或 `opaque`/`transparent` 背景时，在线生图、智能画布和电商工作台都会把对应参数提交到统一生图接口；默认背景为不透明，透明背景结果使用 PNG。
- GPT Image 2.5 的尺寸提交满足 16 像素对齐、长边 3840、总像素 8,294,400 和 3:1 比例限制；3:4 4K（2448×3264）可正常提交，方形 4K 不应提交 3840×3840。
- 在线生图页默认应显示“本地 ComfyUI”，不需要 API Key，也不会产生云端费用；文生图结果应来自 `Z-Image.json`。切换“去噪 / 去色块 / 保构图”并添加参考图后，结果应来自 `Z-Image-Enhance.json`，历史中只出现本地最终图片。调节去噪强度应提交 `0.1–1.0`；ComfyUI 离线时不得创建任务，也不得发起云端生图请求。
- 9:16 长图用自适应网格展示。
- 生成素材提供“全部生成 / 图片 / 视频”渠道，同时显示图片和视频；视频卡片有首帧预览，可预览、下载、勾选删除，且不会误显示为图片。
- 开始生图时可授权系统通知；成功和失败都能在 Windows/浏览器通知中心看到，Service Worker 通知失败时仍能回退显示。

## 4. 小美画布

智能改图交互回归运行 `node --test tests/smart-edit-regions.browser.cjs`：覆盖多区域指令确认与修改、取消与删除、坐标和参考图、重复发送、上传失败、关闭期间的上传以及再次生成。测试使用隔离画布和模拟生成响应，不读写用户画布、不调用付费接口；真实模型对修改要求的执行效果需另行验收。

- 粘贴静态图片后应直接显示已解码的本地预览，节点四角不出现额外白色卡片底。
- 普通绘画节点底部显示在线 API 的提示词、模型和尺寸选项；ComfyUI 工作流节点在节点内编辑参数。旧绘画节点保存为 ComfyUI 时，选中后底部应恢复在线 API 选项；使用专用 ComfyUI 节点后新建绘画节点不应继承其工作流来源。
- 画布图片生成参数栏不显示“生成方式”；普通生成、重生成和节点链路都应提交异步任务并轮询，旧设置中的同步值也应按异步处理。
- 图片工具栏不再提供“高清放大”。
- 滚轮在节点空白区域仍可缩放画布。
- 滚轮缩放按帧合并输入，松手后不再自动缓动；鼠标指向的画布位置保持稳定，跨过 1:1 倍率时节点阴影、滤镜和已显示的工具按钮不应闪烁。回归脚本：`tests/canvas-viewport-startup.browser.cjs`。
- 多图节点放大停稳后应升级清晰度，拖动期间不切换图片源；高清加载失败或删除节点后旧请求返回时，不应出现空白或串图。多节点平移与缩放时图片不应出现矩形缺块。隔离回归：`node --test tests/canvas-image-resolution.browser.cjs`；PowerShell 中先设置 `$env:CANVAS_TEST_ELECTRON='1'` 可用项目 Electron 隐藏窗口运行同一测试，测试后用 `Remove-Item Env:CANVAS_TEST_ELECTRON` 清除选择。测试使用独立临时会话；另需在桌面端用实际画布检查连续拖动、放大和缩小。
- 多选后批量连接稳定。
- 创建菜单可新增“多维表格”和“视频时间线”；表格编辑后刷新仍保留行列与单元格，连接表格到 LLM/Agent 后，上游表格文本会显示并进入请求。
- 时间线连接本地图片/视频/音频后可调整顺序、时长、音频位置和音量；安装 FFmpeg 后点击“导出 MP4”应在 `output/canvas-videos/` 生成可播放文件，并可由下游节点继续引用。未安装 FFmpeg 时应显示明确配置提示；连接项目外路径时接口应拒绝。
- 从图片节点右侧加号拖到空白处松手后，节点菜单应保持打开；选择绘画节点后应自动连到来源节点，选择“分组”后应把来源图片本身收进组并保留原连线。回归脚本：`tests/canvas-create-from-output-port.browser.cjs`。
- Alt 拖动普通节点后，副本保留原节点的上下游连线；上传节点副本不保留连线。多选复制时，不涉及上传节点的选中节点之间连线仍应连接到对应副本。
- 按住 Alt 拖动分组内的单张图片，应创建独立副本，组内原图、顺序、尺寸和连线保留；单图分组也支持。普通拖动仍将图片移出分组，撤销一次恢复整次操作。
- 图片文件名默认隐藏，仅点击选中的图片显示；切换到其他图片或点击空白处后隐藏旧名称，双击已显示的名称仍可重命名。隔离回归：`node --test tests/canvas-group-image-drag.browser.cjs`。
- 解散智能分组后，原连线应恢复到对应的独立图片节点；保存并重新打开画布后再解散，连线仍应保留。旧画布没有来源记录时，分组连线应连接到拆出的节点。回归脚本：`tests/canvas-ungroup-connections.browser.cjs`。
- Ctrl + 鼠标右键拖动擦除连线。
- 生成结果不会挤入参考图槽。
- 在 ComfyUI 工作流卡片或详情点击“导出到小美画布”后，应打开画布并在视口中心创建工作流节点；节点保留标题、动态字段和就绪状态，能接收正式上游素材连线并复用 `/api/canvas-comfy-tasks` 运行。原始工作流库条目应先按现有启用流程建立可执行引用；未准备工作流只能显示需准备状态，不得伪装为可运行。
- 本地模型页应把 Qwen-VL 等目录型模型的每个权重分片识别为同一工作流正在使用；点击受保护权重的“删除模型”时应显示具体应用/工作流名称并阻止删除，刷新或直接调用删除接口也不能绕过检查。
- 循环批量生成多轮结果后，输出会按生成顺序自动合并为一个图片组节点；再次运行时旧整组结果进入历史分组。
- 从节点菜单新建“批量生成”应显示普通循环节点，可设置串行、最多同时 2 轮并行、多图一轮、起始序号和提示词轮换；连接绘画节点后可运行、停止，并保留单轮失败与异步恢复行为。
- 打开已有图文配对节点应保留原有图片与提示词对应关系、运行设置和结果；打开旧画布或由 Agent/计划创建的普通循环节点时仍显示原有高级布局。
- 用户拉大的结果节点在完成/重生成后保持尺寸。
- 对比节点可从节点菜单创建；连接两张图片后按图片比例显示滑动对比，点击“放大查看”可在图片预览灯箱中继续对比，第三个输入会提示最多两张。
- 重新生成替换旧结果。
- 扩图生成后外围由模型补全，中心原图像素、人物姿态和细节保持不变；仅与扩展区相邻的窄幅边缘会平滑过渡，透明扩展区域不会先被白底污染。仅拖动左/右/上/下任一圆点时，其他边不得残留初始预览的透明区；上游返回相邻比例后，原图边界不得因裁切而出现窄条错位。
- 扩图完成后，使用任意普通图片节点继续生图时，结果不得出现扩图原图的中心叠层，也不得被标记为 `outpaint_center_locked`。
- 局部修复能选择正确参考图并调整四点透视；智能改图能进入沉浸式预览、填写底部修改描述、添加蓝色编号定位标记，点击发送后创建并运行保留原图的新改图节点。
- 预览图片上右键可显示“复制图片”；点击后图片可粘贴到其他应用，且 Ctrl + 右键拖动仍只用于擦除画布连线。
- 选中包含多张图片的图片节点或智能分组后，工具栏应显示“批量去背景”；点击后只准备一次本地模型，按原顺序逐张显示“第 n/总数”进度，成功结果新建“透明底”图片组并与原组自动连线，原组保持不变。视频、音频等非图片跳过；部分失败只保留成功图片并显示失败图片及原因，全部失败不创建空组。单图工具栏和预览右键菜单仍保持“去背景”的单图行为。
- 扩图底部能按已配置 API 平台选择图片模型；`Auto` 控件打开比例选择，`4K` 控件打开 Auto/1K/2K/4K 分辨率选择，生成张数控件可选择 1–8 张；点击播放后应按所选张数提交扩图任务，扩展后的透明底图作为参考图，生成结果锁定中心原图，并在相邻扩展边缘平滑过渡，失败时显示错误提示。
- Photoshop 插件回传图层后，目标画布自动出现图片节点。
- Agent 平台和模型来自动态配置；顶部支持模型设置、Skills、历史删除和新对话；Agent 模式优先使用当前手动选择的 Skill，清除后才从现有 Skill 库自动关联任务，回答可创建画布任务、写入提示词或写入并运行。面板不再显示独立的来源节点卡片，底部输入区中的单张引用图仍可移除且不会删除画布原图。动作、计划和在线生图任务应能看到对应的 `skill_id/skill_name` 来源信息。
- 画布底部“偏好 → Skill”应弹出类似图 3 的紧凑搜索列表，输入名称或说明可以过滤；列表中应能看到 `browser-agent`（网页操作助手），点击后当前 Skill、共享选择和消息来源均更新，右上角积木按钮仍能进入完整管理面板。
- 画布内 Agent 节点打开“Skill 库”后应显示搜索框和“管理”入口；在 Skill 列表、搜索框或节点其他内容上滚轮，只滚动 Agent 节点内部，不得改变画布缩放。
- 选中 `browser-agent` 后，即使画布没有节点也可输入“打开 https://example.com”“读取页面”“截图”“列出媒体”；应打开独立的可见浏览器并在对话中返回摘要或截图。输入“点击发布”应先显示需要确认，不得盲点外部提交按钮；媒体下载应生成 `output/browser-agent/` 下的文件链接。
- GPT 对话顶部的“Skill”按钮能加载包式技能库和兼容的 `data/agent_skills/*.md`，导入区只显示“选择文件夹”、自动检查结果和一个“导入”按钮；导入成功后列表数量应从 50 变为 51，并出现“营销心理学专家”，详情自动定位但当前对话仍显示“通用助手”，只有点击“使用这个 Skill”才切换。“添加 Skill”仍能创建并立即启用新的 Markdown Skill。
- GPT Agent 上传产品图后输入“分析一下，我想做直通车图，给我文案/思路”时只能返回文字，不得调用图片模型；即使当前 Skill 偏向视觉生成也一样。明确输入“生成一张直通车图”时先出现可编辑文案卡，修改后点击“确认生图”才开始生成，复制文案或停留在草稿状态均不得产生生图请求。
- 包导入验收：`POST /api/agent-skills/inspect-package` 对桌面包返回 50 个条目、50 个有效条目，缺少 `_meta.json` 的两个包有可见警告；重复导入应跳过而不是覆盖。检查 `SKILL.md`、`references`、`scripts`、教程和示例仍在 `data/agent_skills/packages/`，桌面原目录哈希不变。
- 标准 Skill 验收：选择或粘贴一个包含 `SKILL.md` 的目录（包括下载后的外层目录）应识别为“标准 Skill 目录”，不再要求 `manifest.json`、`_meta.json`、ZIP、教程或示例；`references/models.md` 等文件应随包复制并可在详情中查看。再次导入同一目录应显示“已存在，未重复导入”，内容变化或同名冲突应先显示“是否覆盖？”；浏览器选择文件夹时，临时上传目录在导入完成后清理。
- 导入状态验收：导入后列表刷新使用 `no-store`；列表请求失败时原有 Skill 仍保留，并显示通俗中文错误，不得静默变成空列表。GPT 与画布 Agent 的选择、扫描、重复处理和“不自动启用”行为一致。
- 能力边界验收：详情和上下文显示脚本/依赖/授权状态；只注入 `SKILL.md` 与正文明确引用的文本参考资料，达到上下文上限时返回截断警告；不会执行 `scripts`、CLI、第三方依赖安装、LibreOffice/Playwright 或 1688 授权查询。
- Agent 计划模式：在底部“偏好”开启计划模式，发送后应先显示需求分析、执行思路和 2–4 个方案；输入“先规划”即使开关关闭也应触发计划；点击任一方案后无需二次确认，应自动创建/修改现有节点、连接、排列并运行，失败时保留可重试的方案卡。
- Agent 明确收到“图像比例是 1:1”等比例要求时，计划卡应显示已识别的比例，最终绘画节点的尺寸参数应使用该比例，不得继续沿用旧的“适配输入”比例。
- 手绘板切换 1:1、4:3、3:4、3:2、2:3、16:9、9:16 后，节点高度和绘图区随比例调整，绘图区不留下大块棋盘格空白；拖动节点缩放手柄时仍保持比例，预览不拉伸，已有笔迹完整保留。撤销可恢复原比例，输出图片的实际宽高应与所选比例一致，下游节点使用这张输出图片。
- Agent 粘贴公开商品链接后应显示“正在读取链接”，回复完成状态中显示链接读取数量；标题、商品字段和页面主图应进入模型上下文。读取失败时应明确降级，不阻塞已有商品图片分析。
- 项目工作区支持缩略图、拖动归类、重命名、项目回收站以及画布回收站；删除项目进入回收站，不会删除其中画布，恢复项目时画布一并恢复，彻底删除项目时画布移回默认项目。
- 画布卡片“更多 → 分享画布”应能创建局域网链接；同一 Wi‑Fi 的另一台设备打开链接后能看到同一画布，编辑者拖动/改节点会自动保存并通过 WebSocket/轮询同步，停止链接后再次访问返回无效。
- 接收方桌面端画布列表应显示“加入协同”；粘贴包含完整 `token` 的邀请链接后，打开独立协同窗口并能使用成员、光标、节点同步等功能。分享者停止软件或撤销链接后，协同窗口应显示链接无效。
- 互联网临时分享应在已安装 `cloudflared` 时显示 `trycloudflare.com` 链接；未安装或隧道启动失败时显示可操作的中文错误，不影响本地画布。分享网关不得访问其它画布、API 配置或生成接口；可编辑链接仅额外允许当前范围内的图片派生上传、去背景和素材打包下载。
- 图片空间入口能切换上传素材、生成素材、本地素材三个子入口；选择根目录后自动建立三个子文件夹，旧目录素材可兼容读取或合并。
- 新上传、素材库导入和新生成媒体应带稳定的 `asset_…` ID；保存或读取画布后，媒体引用同时含原 URL 与 `asset_ref_id`。
- `GET /api/assets/{asset_id}/references` 应列出实时画布和历史引用；被引用素材的删除请求返回冲突，文件仍留在原位置。
- 无引用的本地素材删除后应位于 `data/asset_trash/`，可通过统一素材接口恢复；只有已在回收站且仍无引用的素材才能彻底删除。
- 删除整个素材库分类后，恢复其中任一素材应重建原分类并恢复其原文件位置。
- `POST /api/assets/index` 只补建旧数据索引，不复制、移动或改写已有媒体文件。

### Agent 文件夹批量改图验收

- 选择含中文文件名、子目录、同名图片和损坏图片的文件夹：逐图编号稳定，损坏图片显示具体错误，原文件内容不变；重复图片可独立选择。
- 描述修改要求后，全部有效图片都有观察和修改计划；超过单批视觉输入数量时分批读取，不漏掉后续图片。模型返回缺失或重复 ID、参考图读取失败时不可执行。
- 修改逐图指令或取消勾选后再确认：只提交勾选图片，逐张只带对应参考图。计划确认前不能创建生图任务；重复点击确认不会重复提交。
- 分别让一张成功、一张失败：保留成功结果和失败原因。单张填写反馈并重试时，不重新生成其他图片；旧结果版本仍保留。
- 执行中暂停、刷新、再继续：已提交任务保持相同任务 ID，暂停期间不派发新的图片。后端重启后显示真实中断状态，通过继续查询已有任务，不自动重发已提交任务。
- 下载单张与整批 ZIP：文件可打开，报告与实际输出对应；输出目录独立，源文件不覆盖。切换画布或新建对话时，不沿用上一对话的文件夹输入；协同分享页没有本机目录入口。

## 5.1 商品分析采集

- “登录淘宝”会打开项目专用、可见的 Edge 到淘宝官方登录页；界面不显示账号/密码输入框，也不把账号、密码、验证码或 Cookie 返回给前端。完成登录后点“我已登录”应显示浏览器会话已连接，再点击“开始分析”会优先使用此本地会话。
- 粘贴淘宝、天猫或 `e.tb.cn` 链接后，前端调用 `POST /api/commerce-analysis/jobs`，能持续看到排队、公开页面、登录等待、浏览器采集和整理快照阶段。
- `GET /api/commerce-analysis/jobs/{id}` 能返回任务状态；`GET /api/commerce-analysis/jobs/{id}/report` 能返回结构化报告；运行中任务支持 `POST /api/commerce-analysis/jobs/{id}/pause`，失败/部分任务支持 `POST /api/commerce-analysis/jobs/{id}/retry`，也可通过 `?module=reviews` 等参数重试单个模块。
- 导入 JSON 走 `POST /api/commerce-analysis/import`，返回 `schemaVersion=2`、`moduleStatus`、`quality` 和 `evidence`；非法内网链接应返回 400。
- 主图诊断只显示当前商品画廊前 5 张，不混入详情图、头像、推荐商品或店铺图。
- 详情页同时保留可见文字和详情图片；详情图片数量不因主图上限被截断。
- 评价、问大家会通过可见页面按商品资源顺序点击并滚动，右侧应显示“正在截屏识别/正在滚动采集评价/问大家”等进度；完成后评价样本优先来自 `rateList`、问大家样本优先来自 `questionList`，若问大家区域已有可见问答但没有可回读响应，则来自点击后问答区域的精确可见问答卡，并保留真实总量/响应计数；未返回的内容保持为空。打开商品页不应启动旧的全页滚动/翻页智能体流程。
- 评价默认最多整理 200 条，支持通过 `COMMERCE_ANALYSIS_MAX_REVIEW_SAMPLES` 或 `XIAOMEI_COMMERCE_MAX_REVIEW_SAMPLES` 调整（最高 5000）；页面显示的总量不等于本次真实样本数。
- 问大家默认最多整理 2000 条问题，按问题 ID 合并跨分页重复项，并保留每个问题的全部 `topAnswerList` 回答；需要更大上限时可在运行环境设置 `COMMERCE_ANALYSIS_MAX_QUESTION_SAMPLES` 或 `XIAOMEI_COMMERCE_MAX_QUESTION_SAMPLES`，最高支持 5000 条。
- SKU/规格页能显示颜色、尺寸、款式、库存和可选组合；页面没有返回 SKU 时明确显示“未返回”，不使用样例数据。
- 概览页不再把主图数量、详情字数或评价关键词换算为商品健康分；只展示模块覆盖率、样本量、来源和证据条数。
- `data/commerce_analysis/snapshots/<job_id>/` 应出现结构化快照；该目录和浏览器用户目录不能进入发布源码包。
- 商品信息区和报告概览应显示本次采集的商品 ID、规范化链接、采集时间、各模块状态、页面显示总量、规范化样本数、真实响应样本数、响应数、来源步骤和缺失原因；每条评价/问大家结果应带对应模块的证据 ID 和来源步骤。
- 评价/问大家核验按钮应分别下载 `/api/commerce-analysis/jobs/{id}/verification.csv` 和 `/api/commerce-analysis/jobs/{id}/verification.json`。打开文件应能核对商品身份、总量、样本和来源；文件中不得出现 Cookie、Token、Authorization、请求/响应头或原始响应正文。
- 用已登录淘宝商品页执行一次评价和问大家采集：核对页面显示商品 ID 与核验文件 `productId` 一致，规范化链接只保留商品身份参数，采集时间属于本次任务；页面总量只能与对应模块的 `totalCount` 对照，展示条数只能与 `sampleCount`/`realResponseSampleCount` 对照。若任一模块既没有对应真实响应，也没有点击后问答区域内的可见问答卡，必须显示缺失/延迟/未请求原因，样本区为空，不能填演示内容；若使用可见问答兜底，核验来源应包含 `commerce-visible-question`。

## 7. 常见故障

### 页面还是旧样式

按 `Ctrl + F5`；检查 HTML 的资源 `?v=`；必要时关闭所有同地址标签页再打开。

### 上传慢或无反应

检查文件大小、存储目录是否可写、后端控制台和 `/api/ai/upload` 响应。素材上传应先给出可见状态，再异步处理预览/分类。

静态图片超过 50MB 时，参考图上传会自动生成压缩上传副本，原始桌面/素材文件不会被修改；画布会提示压缩前后大小。动态 GIF/WebP、视频、音频和文档不会自动转码，仍需先自行压缩或拆分。

### Antigravity CLI 启动失败

在“API 设置 → Antigravity CLI”重新检测 CLI；未安装时点击“安装 / 更新”，安装后运行 `agy` 完成登录。程序会跳过已失效的 CLI 配置路径，继续查找 PATH 和 WinGet 安装目录。更新程序后需重启小美画布以加载后台修复。

### 一直生成中

检查第三方平台后台任务、任务 ID、轮询地址、成功状态字段和超时设置。前端必须在超时/失败后结束转圈并显示错误。

如果生成日志已有全部图片，画布仍留下生成占位格，先从日志打开图片，不要重复点击生成。保存画布后重新打开，会按原任务编号查询并补回已完成结果；撤销或同步恢复到生成中的节点快照时，也会恢复查询，不重新提交生图。等待格数量以未完成任务列表为准。开发回归运行 `node --test tests/smart-canvas-task-results.test.cjs tests/smart-canvas-task-progress.test.cjs tests/smart-canvas-task-completion.browser.cjs`；浏览器测试在独立模拟画布中运行，不读写用户画布或调用付费接口。

画布任务状态会写入 `data/canvas_tasks.json`。服务重启时，无法继续运行的 queued/running 任务会被标记为“服务在生图任务进行中重启，后台任务已中断”，前端不再因为内存任务表清空而显示 404；此类任务需要重新生成。

画布保存采用同目录临时文件、JSON 校验和原子替换；如果保存过程被中断，应该保留上一次完整画布，而不是出现“项目里少了一个画布”。


### Qwen3 VQA 找不到模型

如果 Qwen3 VQA 报 `LocalEntryNotFoundError`，先看错误卡列出的“当前可用本地模型”，并在节点中选择完全一致的模型名。独立 ComfyUI 默认启用离线模式；缺少所选模型时不会自动联网下载。节点会检查独立环境的 `models/prompt_generator`，以及共享的 `ComfyUI/models/LLM/Qwen/<模型名>`；例如已有 `Qwen3-VL-4B-Instruct` 时，应选择该名称。`Qwen3-VL-8B-Instruct-FP8` 与 4B 权重不是同一个模型，不能只改文件夹名伪装替代。

### `画布任务不存在` / `任务已失效`

旧版本创建、且尚未写入任务记录的任务无法恢复，只能重新生成。升级后的新任务会保留任务状态；若第三方平台已经返回上游任务编号，失败卡片仍可使用该编号查询，不会自动重复扣费。

画布 Agent 如果显示 `Failed to fetch`，新版会先用本次请求的关联 ID 查询服务端是否已经创建任务，找回成功后继续轮询，不会重复提交生图。若仍提示“无法连接本地生图服务”，请确认 `http://127.0.0.1:3000` 仍在运行；如果任务卡随后显示 503 或上游不可用，则是所选图片平台暂时不可用，应在确认额度/平台状态后再手动重试。

画布 Agent 如果停在“正在匹配 Skill 并整理请求”，通常是 Skill 自动路由使用的聊天模型没有返回。新版等待 30 秒后会自动跳过 Skill 匹配并继续通用 Agent；Agent 主请求默认总预算 90 秒，发现同平台聊天模型返回 429/5xx 或无响应时，会按已拉取模型自动切换最多 2 个备用模型。若仍超时，可检查聊天模型、网络以及 `CANVAS_LLM_TIMEOUT`、`CANVAS_LLM_ATTEMPT_TIMEOUT` 和 `CANVAS_LLM_FALLBACK_MODELS` 配置。

`browser-agent` 如果提示“未找到 Node.js”或“浏览器技能服务未能响应”，检查本机 Node.js、Playwright 和 Microsoft Edge 是否可用，再检查 `GET /api/browser-agent/status`；不要把其他软件的用户目录复制到 `data/browser_agent_profile/`。如果网页停在登录、验证码或滑块页，应在可见浏览器中手动完成后重新发送读取/截图指令。

GPT 对话 Agent 如果停在“正在判断并调用合适的工具”，普通问答和图片分析会直接跳过意图路由，避免同一张参考图重复发送；需要判断生图/改图工具的请求，路由默认最多等待 30 秒，最终回答默认最多等待 90 秒。选择 GPT CLI 时，普通文字请求使用聊天专用的低推理强度、只读临时 CLI 会话，并默认强制走 HTTPS，避免 WebSocket 失败时连续重连；默认最多等待 180 秒，界面显示“GPT CLI 正在生成回复”，不再误显示为工具路由。上游在返回前断开时会自动重试一次；仍失败应切换聊天模型。可在 `API/.env` 调整 `CHAT_AGENT_ROUTER_TIMEOUT`、`CHAT_AGENT_REPLY_TIMEOUT`、`CHAT_AGENT_RETRIES`、`CHAT_AGENT_RETRY_DELAY`、`CODEX_CHAT_REASONING_EFFORT`、`CODEX_CHAT_TIMEOUT`、`CODEX_CHAT_FORCE_HTTPS` 和 `CODEX_CHAT_BASE_URL`。

商品分析右侧“问问小美”使用独立的流式超时，默认最多等待 300 秒；在真正开始计时后，模型首段文字默认最多等待 60 秒，详情视觉参考最多均匀抽样 6 屏、单次最多发送 10 张视觉图，避免视觉输入过多时空等。快捷分析仍会按评价、主图、详情页等模块裁剪快照和参考图，且失败重试不会把历史视觉参考重复叠加。仍需调整时可在 `API/.env` 设置 `COMMERCE_CHAT_STREAM_TIMEOUT`、`COMMERCE_CHAT_FIRST_TOKEN_TIMEOUT`、`COMMERCE_CHAT_DETAIL_REFERENCE_MAX` 和 `COMMERCE_CHAT_MAX_INLINE_IMAGES`。

如果搜索结果页仍显示“请先完成当前商品采集”，先确认当前地址是淘宝/天猫搜索页而不是详情页，并确认桌面壳已重新加载 `static/commerce-analysis.html` 引用的最新资源版本。Electron 路径检查 `commerce:capture-page-context` 返回的 `pageType=search`；兼容页面检查 `POST /api/commerce-analysis/page-context`。搜索页即时分析不应等待 `GET /api/commerce-analysis/jobs/{id}` 轮询；详情页评价、详情图等深度模块仍需走任务采集。

六站点页面显示“等待可读资料”或“需要登录/验证”时，先在当前小美画布桌面标签内完成页面加载、登录或验证，再点右侧刷新按钮。读取成功后，“问问小美”内必须出现当前页面实况卡，不能只停留在“正在读取”；实况卡只列当前页型已提取的字段和该站点允许的资料资源，不代表模型已完成分析，也不能显示整页可见文字。检查 Electron preload 是否暴露 `captureAssistantContext`，主进程 `commerce:capture-assistant-context` 是否返回 `source=electron-visible-dom-assistant`、`structured.facts` 和 `structured.resources`；若某个平台出现其他平台的资源标签，优先检查页型识别和资源 ID 白名单。不要用复制 Cookie、开发者工具脚本、跨域 iframe 或第三方用户目录作为替代。普通浏览器模式无法读取跨域页面是预期限制。

商品链接出现“来不及扫码”时，确认可见 Edge 没有被手动关闭；可见页面浏览器采集在登录/验证页默认等待最多 90 秒，超时后也保留窗口。完成扫码或验证后回到失败卡点击“重试”；如需调整桌面版可见滚动次数，可设置 `XIAOMEI_COMMERCE_VISIBLE_SCROLL_PASSES`，如需恢复浏览器兼容等待流程，可在 `API/.env` 设置 `COMMERCE_ANALYSIS_FAST_BROWSER=0`。

### 1688 首页已登录，商品页仍要求登录

完整退出并重新启动小美画布，再打开 1688 商品链接。若商品页仍要求登录，在该商品标签点击“登录1688”完成官方登录，然后重新打开或刷新商品页。1688 的官方统一登录跳转和新商品标签应共用同一会话；已有淘宝登录不会替代 1688 登录，无需清空浏览数据。

1688 页面沿用历史电商会话，除了 Cookie 还会保留站点使用的 Local Storage、IndexedDB 和登录跳转缓存，因此从首页点击商品、新建商品标签或刷新时不会因为换分区再次要求登录。旧版本已创建的 `persist:xiaomei-1688` 目录不会覆盖当前会话。开发回归执行 `node --test tests/desktop-commerce-session.test.cjs`，并手动验证：1688 登录完成后从首页打开两个不同商品，刷新和切换标签均保留登录状态；淘宝、千牛和生意参谋仍使用各自原有会话。

点击页内“立即登录”后出现“加载失败”时，先完整重启桌面端加载更新后的导航处理。开发回归另用项目 Electron 执行 `tests/desktop-1688-login-navigation.electron.cjs`：它在独立临时会话中验证登录框和主页面的真实 Chromium 跳转事件，不访问线上登录服务。`will-frame-navigate` 的地址和主框架标记从事件对象读取；首页加载完成后的同页登录也必须建立登录导航目标。

### `Service temporarily unavailable` / `unknown_error`

这是聊天模型上游通道临时不可用，不是参考图、画布连线或本地文件损坏。后端会在同一模型上自动有限重试；仍失败时，在 Agent 失败卡点击“重试请求”，或切换到 API 设置中已拉取的其他聊天模型。可通过 `CANVAS_LLM_RETRIES=0` 关闭自动重试。

### 平台显示成功，本地缺图

记录原始响应结构，检查所有 URL/base64 容器和数组是否完整遍历；不要写死最多三张。

### `not supported model for image generation`

选择了对话模型或模型分类错误。重新拉取模型并确认其属于图片模型。

### 重启后设置丢失

检查浏览器是否清理了 `localStorage`，以及设置变更事件是否调用持久化。服务端平台配置检查 `data/api_providers.json`；多账号 Key 记录检查 `data/api_key_profiles.json` 和 `API/.env` 中对应的 env 别名。不要直接在日志或浏览器控制台打印 Key。

### 端口占用

```powershell
Get-NetTCPConnection -LocalPort 3000 -ErrorAction SilentlyContinue
```

桌面端会先尝试 3000 端口；如果 Windows 保留了该端口或已有进程占用，会自动选择后续可用端口并由 Electron 连接对应服务。不会自动打开系统浏览器；实际端口以服务日志中的 `Uvicorn running on ...` 为准。

### 互联网临时分享无法创建

首次点击互联网分享时，应用会从 Cloudflare 官方发布地址准备 `cloudflared.exe`；如果网络受限，可手动安装后在 PowerShell 中执行 `cloudflared tunnel --url http://127.0.0.1:3000`，或设置 `XIAOMEI_CLOUDFLARED_PATH`。Quick Tunnel 仅用于临时测试，重启软件后地址会变化。

### 桌面窗口点 × 没有退出

正常关闭会清理内嵌商品页面并取消启动时的窗口显示定时器。页面阻止关闭或关闭超过 3 秒时，会提示“继续等待”或“强制关闭”；强制关闭可能丢失尚未保存的内容。修改桌面代码后需完整退出并重新启动，刷新页面不会加载此修复。

开发回归：使用项目 Electron 执行 `tests/desktop-window-close.electron.cjs`，覆盖正常关闭、页面拦截、继续等待、强制关闭、关闭超时、商品页面释放和启动定时器取消。

## 扩图与 AI 分层验收

- 扩图：验证四边与四角拖动、原图拖动、Alt 对称调整、固定比例及原图保持在外框内；生成后原图节点保留，新增扩图节点与原图连接。结果尺寸应与扩图框一致，原图区域（含边缘）按编辑器中的位置保留，不被拉伸或裁掉。模型返回比例偏差超过 3% 或原图保护失败时任务报错，不将未保护结果作为成功图片。开发回归执行 `python -m unittest discover -s tests -p test_outpaint_preserve.py` 和 `node --test tests/outpaint-results.test.cjs tests/outpaint-geometry.test.cjs`。
- 分层：从图片工具栏选择 AI 分层，验证智能/自定义层数和动态模型选择、并发数量、自动纠错次数与调用上限、逐层进度、透明 PNG、合成预览、关闭后重新打开记录、停止与继续、单层重试。元素归属冲突应停止生图；自动纠错不能重做通过的图层，也不能因重启而超出预算。
- PSD：导出后在 Photoshop 打开，核对尺寸、图层名称及叠放顺序；切换各层可见性并移动图层，双击智能对象确认嵌入原图可读取；隐藏原图对照层不应覆盖合成结果。
- Photoshop 桥接：加载更新后的 UXP 或 CEP 插件，保持面板在线；点击“在 Photoshop 打开”，应建立新文档并保留独立图层。画布先显示队列状态，再显示插件的打开回执。没有更新插件时应提示更新；重复点击同一版本不能新建多个队列项。插件导入失败必须显示失败，不能被误记为完成。代码测试见 `tests/test_image_layers_photoshop.py` 与 `tests/image-layers-photoshop-plugin.cjs`，这些模拟接口不代替 Photoshop 实机验收。
- 若提示模型没有返回有效透明背景，检查所选模型的透明输出能力；绘制在图片里的棋盘格不是透明通道。换模型重新分层或重试问题图层后复核商品与文字。
- 若“继续处理”仍显示生成失败，先检查已有图片任务记录；它优先查询原上游任务、恢复保存的生成回执或续查即梦排队，不会因网络错误重新生成。没有可恢复结果时，确认原任务状态后使用该层的“重试”。服务重启后保留原任务编号和已消耗的纠错次数，不能将中断任务误报为仍在生成。

开发验证使用 `tests/test_image_layers.py`（模拟模型，含恢复与失败路径）、`tests/outpaint-geometry.test.cjs`、`tests/image-layers.browser.cjs`（浏览器交互及 PSD 读回）、`tests/image-layers-psd-stress.browser.cjs`（4K 导出与打包期间页面响应）和 `tests/image_layers_app_smoke.py`（独立临时目录启动，不读取用户配置）。模拟模型验证不代表真实模型分层质量已验收。PSD 打包失败时先刷新更新资源，确认 Worker 脚本可加载；大图仍受内存和层数限制，必要时降低分辨率。
