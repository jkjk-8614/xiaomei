# 本地 AI 应用库

## 日常使用

打开侧栏的 ComfyUI，在左侧工作流列表选择工作流。中间表单按工作流提供商品图上传、提示词和“生成参数”，点击“生成”后在右侧查看和下载结果。纯文生图工作流不显示图片上传，没有提示词输入的放大工作流不额外添加提示词。首次打开已有工作流会自动建立简单表单配置，原图仍由 ComfyUI 执行。刷新页面会恢复当前工作流及任务查询。服务进程中断与页面刷新不同：无法续接的任务会按现有任务机制记录为中断，不会自动重跑。

“更多 → 高级编辑”打开原生节点编辑器。“更多”中的“画布设置”仍管理原有画布工作流；应用使用同一套工作流文件、字段配置和生成后端。

含多个分组的 UI 工作流会在简化表单顶部显示“工作流分组”，包括原文件中已旁路的分组。选择分组后，系统启用该组及连线所需的上游节点，生成独立的表单与可执行副本；原工作流及已有画布引用保持不变。仅包含 DLSS5 设置节点的“低 / 中 / 高”分组作为增强档位显示，不作为独立可运行分组。含 rgthree 图像对比节点的分组，如果外部输入全部来自同一分支及其上游，会随该分支一起启用，包括组内的拼接、预览和保存节点，不再单列入口；跨分支对比仍保留独立入口。分组完成转换后可单独导出到小美画布。

如果应用环境已经准备完成、但桌面端重启后本地 ComfyUI 尚未运行，点击“生成操作表单”会自动启动已准备的独立环境并完成一次本地转换；画布和应用库的上传、运行入口也会自动启动已准备的独立环境，无需重新安装或下载模型。启动期间请等待；启动失败会显示具体原因。外部 ComfyUI 仍需先手动启动。

打开应用会重新检查当前连接的 ComfyUI 节点。依赖区先显示待补齐项目，再显示可安装和已准备项目；模型按主模型、文本编码器、VAE、LoRA 等用途标注，并保留完整文件名与目录。已安装的转换桥接不会因工作流尚未生成表单而再次列为待安装；节点齐全后可在当前页面自动转换，失败时用“生成操作表单”重试。

简化操作侧栏列出用户导入的应用，以及工作流目录中尚未启用的用户工作流；同一工作流启用应用后只显示一次，不自动加入其他功能使用的预置工作流。原始工作流库继续用于高级设置和模型引用检查，共用模型的保留判断不受侧栏筛选影响。状态分别区分“环境准备完成”和“工作流可运行”，安装进度到 100% 不会掩盖缺模型、缺节点或待转换。

已有工作流首次打开后可通过“管理工作流 → 删除工作流”清理。删除前显示原工作流是否移入回收区，以及独占、共用、手动保留和无法确认的模型清单。预置工作流也可在此移除；依赖该工作流的其他功能需要重新导入后才能使用。

工作流列表在使用表单时保持可见，支持搜索和状态筛选。窄屏改为顶部横向列表、表单和结果上下排列。

## 导出到小美画布

工作流卡片和工作流详情都提供“导出到小美画布”。点击后，应用库把可执行工作流引用、标题、动态字段和当前就绪状态交给画布；如果条目仍来自原始工作流库，会先按现有“启用为应用”流程生成可执行 API 图，不复制或改写原始工作流。画布会在当前视口中心创建一个“ComfyUI 工作流”节点，并把字段配置保存到节点自己的运行设置中。

工作流节点可以像绘画节点一样接收正式输入连线。上游图片、视频和音频会按工作流字段类型接入，节点运行继续使用 `/api/canvas-comfy-tasks`、本地任务轮询、历史和素材登记链路；点击节点底部“运行工作流”执行，首次运行会在右侧创建独立结果节点，后续运行复用最近的结果节点并替换其中的图片，保留运行记录、节点位置和已有连线，旧图收进历史分组；原工作流节点继续显示参数。节点显示“可运行 / 需准备 / 需补齐依赖”等状态，未准备完成的工作流可以先导出，但运行前必须回到 ComfyUI 工作台补齐依赖。

第一版只把 ComfyUI 工作流封装为画布节点，不在画布内编辑 ComfyUI 的内部节点图。工作流的字段、依赖、模型和高级节点编辑仍以 ComfyUI 工作台为准；修改工作流后重新导出或刷新节点即可。

本地 ComfyUI 从主侧栏“更多设置 → ComfyUI 设置”进入已有工作台。这里可以配置一个或多个 ComfyUI 后端地址，并读取现有 `/api/workflows` 与 `/api/comfy-apps/catalog`；不复制工作流文件，也不把本地工作流混入普通在线 API 节点的来源下拉框。工作流字段仍以 ComfyUI 工作台的工作流设置页为准。

在小美画布的创建菜单选择“ComfyUI”，会创建独立的 ComfyUI 工作流节点。节点选择已有工作流，提示词以及上游图片、视频、音频按已配置字段接入，继续通过 `/api/canvas-comfy-tasks` 执行。工作流内部节点图仍在 ComfyUI 工作台中编辑；已有从工作流卡片“导出到小美画布”的入口和旧的独立节点继续兼容。

在“更多 → 画布设置”删除应用自己生成的工作流后，后端会把同名 AI 应用配置移入 `ComfyUI/comfy_apps_deleted/` 回收区，并通过 `workflows-changed` 通知应用库刷新。这个同步只移除过期应用配置，不删除模型、共用工作流或手动保留模型。

点击“删除工作流”时，系统先检查模型引用。确认后，应用配置、应用生成的 API 图，以及没有被其他应用引用的来源工作流移入 `ComfyUI/comfy_apps_deleted/` 回收区，输出结果和历史记录保留。只删除未被其他应用、保留的工作流或画布使用、未手动保留、且位于模型目录内的已确认文件。共用模型、手动保留模型、外部路径、同名歧义或无法找到的模型不会自动删除。执行时会再次检查引用，独立 ComfyUI 环境和自定义节点保留。

顶部“本地模型”会扫描主 ComfyUI 模型目录、应用独立环境模型目录和应用补全权重目录，列出模型文件、相对位置、大小、修改时间及引用关系。像 Qwen-VL 这样由工作流按目录名引用、实际由多个权重分片组成的模型，会把目录内每个权重都关联到对应应用和工作流，不能绕过引用保护单独删除。勾选模型旁的“手动保留”后，它会被单独标记为“手动保留”，删除使用它的应用时也不会删除模型；取消勾选不会解除“共用·保留”模型因其他应用、工作流或画布产生的保护。“暂未发现引用”只表示当前扫描范围没有找到引用，不代表可以随意删除。点击受保护模型的“删除模型”会列出具体占用它的应用或工作流，并提示先更换模型或移除引用；未被引用且未手动保留的模型才会进入删除确认，确认后会再次检查引用，再从本地模型目录移除文件。删除不可撤销。删除应用前仍以删除预览的安全检查为准，不以列表状态替代确认。

## 导入工作流

点击“导入工作流”选择普通 ComfyUI JSON 或 API JSON。同名导入创建新副本，不覆盖已有应用。原始图保存在 `ComfyUI/comfy_apps/<应用ID>/app.json` 中。

导入后会自动安装可核验来源的缺失节点并准备转换桥接。系统先使用项目固定可信清单；清单中没有的节点会按节点类型在 ComfyUI-Manager 公共节点映射中做完全一致匹配。只有匹配到唯一仓库、仓库同时登记在 Manager 节点清单、来源是无凭据的 GitHub HTTPS 地址，并且安装前能够解析为 40 位固定提交时，才会自动安装。映射与提交写入独立运行目录的本机缓存；公共目录暂时离线时可以复用此前已核验的固定提交。找不到来源、来源冲突或安全校验失败时会显示具体原因，不会按相似名称猜测、替换节点或改写工作流。

工作流列表底部的“导入后自动寻找并下载模型 / LoRA”默认勾选，也可提前关闭，选择会保存在本机；关闭只停止模型查找与下载，不影响节点安装。开启时，导入完成且安装前检查允许后会自动寻找缺失模型和 LoRA，下载可核验的匹配文件并准备依赖；右侧显示正在查询的平台、下载进度并可取消。如果导入时本地 ComfyUI 未连接，系统会先启动独立环境并扫描原工作流，再安装新发现的缺失节点。安装后会重启独立 ComfyUI，并通过实际节点接口重新检查工作流需要的节点；仍有缺失时显示“准备未完成”及节点名称，不会报安装成功。

首次打开工作流时，原始 `workflows` 文件作为来源和 UI 布局保存；可执行 API 图写入 `ComfyUI/workflows/custom/app_<应用ID>.json`，转换和切换参数不会覆盖原始工作流。删除时的回收规则见上方“日常使用”。

普通 JSON 先保存为待准备应用。导入详情会先展示安装前检查：操作系统、内存、GPU/显存、工作区磁盘，以及已准备、可自动安装、需要手动准备的依赖。对登记在可信清单中的公开模型会显示“自动安装”或“自动下载并安装模型”按钮；点击后模型直接放入本机 ComfyUI 对应目录，页面显示真实下载百分比并在完成后自动复查。关闭模型自动下载时，节点仍自动准备，模型可点击安装按钮补齐；硬件或本机 ComfyUI 基础环境明确不满足时不会启动安装，并给出下一步。准备中的进度条按真实安装阶段更新；下载源没有提供文件百分比时显示“处理中”，不伪造下载比例。页面通过独立的隐藏 ComfyUI 前端调用 `app.graphToPrompt()`，转换后生成表单。转换失败会保留原文件和原因，也可以在环境准备后点击“生成操作表单”重试。

安装器处理已登记模型，以及工作流模型元数据中提供的 Comfy-Org 官方 Hugging Face safetensors 直链。后者要求文件名、模型目录与工作流需求匹配，转换后仍保留匹配的来源。无法确认来源的缺失节点、云端节点、受授权限制的文件和仅有文件名但没有来源的模型会列为待处理项。当前本机 ComfyUI 已安装并在节点接口中提供的第三方节点可以运行；新发现的节点只有通过上述来源检查才会自动安装。安装完成后仍会重新检查工作流，未补齐的项目不会标为可运行。下载使用临时文件，校验并改名完成后才算安装成功；取消或失败会保留可续传文件，但不会标记模型已安装。

表单只包括有效输出所依赖的输入。模型加载参数不放在日常表单中；种子、尺寸、步数等放入“生成参数”。应用名称、输入项名称和顺序可在“管理工作流 → 编辑表单”中修改。转换不会把原作者图片路径当作已上传素材。若 DLSS5 图片增强工作流含独立的“低 / 中 / 高”设置分组，表单和画布节点会显示“增强档位”；“原工作流默认”保留原来的运行方式。画布节点选择档位后会显示该组的全部设置参数及原工作流数值，修改值随本次运行提交；每个档位的修改分别保存。运行时接入对应的设置节点，原始工作流不变。

如果工作流包含 SwarmUI 风格的 `SwarmWorkflowDescription`、`SwarmInputGroup` 和 `SwarmInput*` 节点，应用库优先使用这些节点的标题、说明、默认值、分组、排序、范围和高级标记生成表单；没有这些节点时才使用普通 ComfyUI 节点的兼容识别。SwarmInput 工作流准备时只加入小美画布的轻量本地兼容桥，不安装完整 SwarmUI。

## 准备本地环境

安装器位于 `ComfyUI/integration/comfy_app_runtime.py`，模型查找位于 `ComfyUI/integration/comfy_model_sources.py`。准备任务先搜索缺失文件，再下载与校验；不执行导入 JSON 或网页中的安装命令。固定可信节点包及版本登记在 `ComfyUI/integration/comfy_node_registry.py` 的 `NODE_PACKAGES`；同一模块的 `NodeSourceResolver` 负责读取 ComfyUI-Manager 的 `extension-node-map.json` 与 `custom-node-list.json`，执行精确匹配、唯一来源检查、GitHub URL 校验、提交固定和离线缓存。缓存为运行数据 `ComfyUI/comfy_apps_runtime/node-source-cache.json`，不进入发布源码包。

缺失项面板提供“安装缺失节点”，只安装已经固定到提交的节点包及其 `requirements.txt` 依赖，重启独立 ComfyUI 并检查所需节点是否加载，不搜索或下载模型。来源未确认、匹配不唯一或不能固定提交的节点仍需从原作者取得。节点仓库属于会由 ComfyUI 加载的第三方代码；公共目录匹配只证明来源可追溯，不等于项目对插件安全性、许可证或运行效果背书。

`DLSS5EasyPipeline` 等 DLSS5 节点固定到 `HECer/ComfyUI-DLSS5` 的已核验提交，安装时同时拉取 Git LFS 文件。该插件是实验性的 Windows/NVIDIA 扩展；节点安装并加载后，首次使用仍需在高级编辑中运行插件自己的“DLSS Runtime Setup (One Click)”，按其界面确认并检查原生 VapourKit/DLSS 运行时。节点自动安装不会替用户跳过该插件对原生 DLL 下载的显式确认。

缺少节点时先安装节点，再生成操作表单；不会继续转换并把缺失节点误报为 JSON 格式错误。依赖检查按当前执行状态处理，UI 模式 2（禁用）和模式 4（旁路）的节点不会阻塞当前工作流，恢复对应分支后会重新检查。rgthree 的纯前端分组控制会结合已加载节点包判断，避免因它不出现在后端 `object_info` 而重复提示缺失。转换成功后会清除旧的转换错误。

默认优先从项目内的 `ComfyUI/` 读取现有安装；未找到时回退到用户 Documents 下的 ComfyUI。目录不同可设置 `XIAOMEI_COMFY_BASE`，指向包含 `core` 和 `.venv` 的目录。

独立环境在项目内 `ComfyUI/comfy_apps_runtime/`：其 Python 环境只读复用现有环境的大型依赖，应用库专用节点和运行数据保存在该目录，不升级主 ComfyUI；运行产物统一写入 `ComfyUI/output/`，便于在 ComfyUI 的媒体资产中查看。独立服务使用本机端口，地址由 `ManagedRuntime.address` 定义。准备过程检查依赖解析、显示阶段进度和日志，支持取消。失败、取消、授权不足或文件清单不完整均不会标记准备完成；取消或失败后可以重新安装，已下载的完整文件会复用。模型传输遇到超时、断流或临时服务错误时会有限次重试并断点续传；权限错误不会反复重试。进度区域原位更新，刷新时保留日志展开状态；失败后提供“重试搜索 / 下载”。

高级编辑通过本地桥消息 `xiaomei-load-workflow` 把当前应用的 UI JSON 加载到 ComfyUI 原生画布，并通过 `xiaomei-workflow-loaded` 返回结果；没有选中工作流时显示选择页，不再默认打开空白的 `Unsaved Workflow`。API JSON 没有节点布局，只能用于应用运行，页面会明确提示，并提供“直接进入 ComfyUI”入口，不能假装提供完整节点编辑。

从应用库打开的工作流如果仍缺少模型，高级编辑顶部会显示“自动安装可用模型”。原生 ComfyUI 对可信清单模型的“下载”请求也会转为同一准备任务，页面显示阶段和百分比进度，文件直接写入对应的 ComfyUI 模型目录，不再打开空白浏览器下载窗口；清单之外的模型也会先尝试搜索。需要授权、没有公开下载文件或匹配不唯一时，在缺失项中展示来源和原因，可重新搜索或取得原文件后点击“导入此模型”。导入已下载文件时，已登记模型还会校验完整文件大小，未完成的临时文件不会被移动。

如果本地服务未连接，高级编辑页会先显示已检查的地址，并提供“启动本地 ComfyUI”“重新连接”和“打开连接设置”。已经准备好的独立环境可以通过启动按钮恢复，使用 `POST /api/comfyui/start`，不会重新下载模型；外部 ComfyUI 仍需先由用户启动。

启动时优先复用身份与输出目录匹配的后台；同一后台仍在启动时继续等待，不重复创建进程。只下载模型、且没有修改节点或本地桥接的准备任务也会复用已启动的后台；安装节点或更新桥接仍需重启，并检查所需节点是否可用。

普通冷启动可读取本机运行数据 `ComfyUI/comfy_apps_runtime/startup-nodes.json`，跳过已核验未引用的节点包，不删除插件。核验入口是 `ManagedRuntime.audit_startup_nodes`，输入必须是完整加载后台的 `object_info`；它检查应用原图、执行图、原参数图、工作流目录和原生编辑器已保存工作流，包括禁用和旁路分支。清单需经独立后台验证后保存，不能直接照搬别人的清单。工作流文件增减、节点类型变化、节点目录增减或 JSON 无法读取时，下次冷启动恢复完整加载；只改参数不影响清单。环境准备启动使用完整加载，之前跳过且已核验安装的节点会重新启用，不重复下载。高级编辑临时导入了尚未保存的其他工作流且提示缺少已安装节点时，先保存或导入应用库，再准备环境。将清单改名为 `startup-nodes.json.bak` 可在下次冷启动恢复完整加载；已运行的后台不会因此被自动重启。

准备模型需要联网下载。已识别云端节点会阻止本地应用执行；已安装的第三方节点由用户本机 ComfyUI 执行，其网络行为由插件自身决定，这些检查不是操作系统级网络沙箱。

SeeThrough 下载来源及模型定义见 `ComfyUI/integration/comfy_app_runtime.py` 的 `SOURCE`、`REVISION`、`MODELS`；内置模型下载清单见 `ComfyUI/integration/comfy_apps.py` 的 `AUTO_MODEL_REGISTRY`；清单外的来源发现见 `ComfyUI/integration/comfy_model_sources.py`。本地文件清单写入 `resource-manifest.json`，重检会核对存在性和大小；下载日志为 `prepare.log`，独立服务日志为 `server.log`。未知下载大小会明确标为待核实，不把不完整下载显示为已安装。

## SeeThrough 图像分层

应用主要面向动漫角色的语义分层。真人和商品效果需要实测，不保证恢复原设计文件或被遮挡的真实内容。

省显存参数由 `AppLibrary.compile` 按节点实际支持的参数应用，界面展示生效值；原参数另存，可在“设置”恢复。原参数显存需求可能更高。首轮未验证时显示“待本机验证”，真实执行失败会保留原因并阻止继续误报就绪。

成功后可下载合成预览、透明 PNG 图层和图层 ZIP。“下载分层 PSD”在浏览器内使用随包提供的 ag-psd 合成 PSD，并保存到本次任务；后续可直接下载。排序和位置沿用插件的图层清单，每次任务使用独立输出前缀，不读取插件的全局最后输出记录。

## 数据与接口

- `ComfyUI/workflows/custom/app_<应用ID>.json`：可执行 API 图。
- `ComfyUI/workflows/**/*.json`：自动发现的原始工作流库；启用应用后仍保留，不被可执行 API 图覆盖。
- 对应 `.config.json`：与现有工作流设置共用的标题和字段配置。
- `ComfyUI/comfy_apps/<应用ID>/app.json`：原图、原参数、准备状态及应用元信息。
- `data/canvas_tasks.json`：共用的运行和准备任务记录。
- 生成文件：现有生成图片存储目录；不覆盖上传原图。去重与 ComfyUI 输入、输出保存规则见 [数据与目录结构](04-数据与目录结构.md#8-comfyui-目录与图片去重)。

本地模型清单是运行时扫描结果，不单独复制模型文件或建立第二套模型存储。

模型的手动保留设置写入 `ComfyUI/comfy_model_preferences.json`，只保存模型标识和显示信息，不复制模型文件；模型文件移动后需要在“本地模型”中刷新并重新确认。

接口在 `ComfyUI/integration/comfy_apps.py` 注册于 `/api/comfy-apps`。除原有接口外，`GET /catalog` 的 entries 返回用户导入的应用和工作流目录中尚未启用的用户工作流，并按工作流来源去重；内部完整目录继续用于工作流与模型引用检查，`GET /workflows/{name}` 查看发现项，`POST /workflows/{name}/enable` 启用简单应用，`GET /models` 扫描本地模型，`POST /models/protection` 保存手动保留状态，`POST /models/delete` 删除用户确认且重新核验为未引用的模型，`POST /<应用ID>/rescan` 重新检查，`POST /<应用ID>/models/import` 把用户确认的模型放入正确目录后自动复查。导入、安装前检查、准备、转换、配置、上传、运行、删除预览、应用删除和 PSD 保存均在该模块内。`GET /<应用ID>/preparation` 返回当前准备任务、阶段进度、日志尾部、硬件检查和依赖分类；准备接口遇到明确硬件硬失败时返回可操作原因，不创建安装任务。运行只接受配置且重新校验的字段，使用去重请求编号，应用任务串行提交到本机后端，不转交在线供应商。ComfyUI 连接状态和已准备独立环境启动分别由 `/api/comfyui/status`、`/api/comfyui/start` 提供。

## 开发验证

单元测试：`tests/test_comfy_apps.py`、`tests/test_comfy_workflow_inspection.py`。真实运行验收脚本位于 `tests/comfy_apps_acceptance.py`、`tests/comfy_apps_artifacts.py` 和 `tests/comfy-apps-results.browser.cjs`。这些脚本默认连接独立测试端口，运行前检查脚本中的地址；验收脚本会创建本地测试应用或使用已有测试结果，不调用付费生图接口。

启动加载与复用回归：`tests/test_comfy_startup_nodes.py`、`tests/test_comfy_runtime_recovery.py`。`tests/comfy_startup_probe.py` 读取已完整启动的后台，在临时目录和独立端口对比完整加载与筛选加载，检查已有工作流引用节点的可用性和接口一致性；不执行生成任务，也不停止日常后台。

## Z-Image-Turbo 依赖说明

硬件检查提供本机显存和官方说明链接。官方 16GB 显存描述作为参考，不当作硬性最低要求；8GB 设备建议先尝试单张 512×512，实际能否运行仍需本机验证。

缺失模型中的 `z-image-Turbo-细节增强v2.safetensors` 已关联到 [RunningHub 同名模型页](https://www.runninghub.cn/model/public/2063991571288256513)。公开页面没有文件下载链接，不能标记为自动可下载。手动导入会校验该页面登记的 SHA-256，校验失败不会写入模型目录。

## 自动寻找模型与 LoRA

导入时保持自动寻找选项开启即可。已有工作流可以展开“查看缺失项 / 下载模型”，点击“自动寻找并下载缺失模型”。搜索与下载复用准备任务，支持取消和重新尝试；结果保存在应用配置的 `model_search`，刷新后仍可查看。

搜索范围包括工作流自带来源、ComfyUI-Manager 公共模型目录、RunningHub 同名条目、Civitai、Hugging Face，以及 Bing 公开网页索引。网页搜索用于发现来源，不代表能遍历整个互联网；搜索受平台收录、网络连接和访问权限影响。界面列出本次查询的平台、来源链接及失败原因。

新发现文件只有在文件名或已知 SHA-256 匹配、文件类型和目录匹配，并取得可核验大小与 SHA-256 时才自动下载；多个同名不同校验值的文件不自动选取。Hugging Face 下载地址固定到仓库版本。自动发现支持 safetensors 与 GGUF；其他格式保留手动导入或既有内置清单下载。下载文件存入原 ComfyUI 对应模型目录，校验失败不标记安装完成，不覆盖已有同名文件。

登录、付费、授权受限或只有展示页的模型会保留为待处理项。不会用名称相近的模型替换，也不会自动绕过缺失 LoRA 改变原工作流。

## 替换模型或 LoRA

“导入此模型”的文件选择、导入状态和错误原因会显示在对应模型下方。选择的文件名与工作流引用不同（包括工作流只提供展示名称、没有实际扩展名）时，页面会自动按“替换模型”或“替换 LoRA”更新对应加载器引用；检查成功后该模型会从待补齐清单消失。

缺少 `Float` 时可更新本地兼容桥接，保留数值输入；完成环境准备并重启 ComfyUI 后重新扫描。`LibLibVisionV2Seed` 的节点与配置需要向工作流作者获取，或在高级编辑中替换为本地图片描述节点并重新连接提示词。导入模型文件不会补齐该节点。

展开工作流表单底部的“查看缺失项 / 下载模型”（可运行时为“模型与运行环境”），在模型旁点击“替换模型”或“替换 LoRA”。可以选择相同模型目录内已有文件，也可以点击“上传另一个文件并替换”。替换采用新文件的真实名称，不要求与缺失文件同名，不按原文件的哈希拒绝替代模型；“导入此模型”仍用于补回原文件，保留原来的文件名与哈希校验。

替换只更新当前应用中该目录、该模型对应的加载器引用，同步可执行图和高级编辑中的图，保持提示词、节点连接和 LoRA 强度。首次替换前的图与表单保存在应用配置的 `model_replacement_original`，替换记录保存在 `model_replacements`；模型文件和其他工作流不会被覆盖或删除。运行、排队或准备期间禁止替换。

上传的 safetensors 会检查文件结构、张量范围及 LoRA 权重类型；目录一致不保证模型架构兼容，需要选择相同基础模型系列，实际兼容性以运行结果为准。替换后重新检查缺失项，不把未实测的替代模型标记为已验证出图。

接口：`GET /<应用ID>/models/replacements?dependency=原引用&category=目录` 查询可选本地文件；`POST /<应用ID>/models/replace` 提交 dependency、category、replacement；上传替换复用 `POST /<应用ID>/models/import`，表单字段 `replace=true`。
