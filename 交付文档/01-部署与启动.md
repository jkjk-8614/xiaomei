# 部署与启动

## 1. Windows 桌面端一键运行（推荐）

本交付包使用 Electron 桌面端承载界面，FastAPI 只作为桌面端的本地服务运行。解压或复制到可写目录后：

1. 将 `API/.env.example` 复制为 `API/.env`。
2. 填写需要的 API Key，或者启动后进入“API 设置”填写。
3. 首次运行如果 `desktop/node_modules/` 不完整，在项目根目录执行 `npm install --prefix desktop`。
4. 双击 `run.bat`，会直接打开“小美画布”桌面窗口。

`run.bat` 不再打开系统浏览器，也不会在缺少 Electron 时回退到浏览器；如果桌面运行组件缺失，会弹窗提示安装命令。桌面端会自动复用或启动本地 FastAPI 服务。

## 2. 仅启动本地服务（开发/排障）

建议 Python 3.10–3.12，64 位。

```powershell
cd 小美画布
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item API\.env.example API\.env
python main.py
```

直接运行 `main.py` 只启动本地 FastAPI 服务，不会自动打开浏览器；日常使用请双击根目录 `run.bat` 进入桌面端。

macOS/Linux：

```bash
cd 小美画布
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
cp API/.env.example API/.env
python3 main.py
```

项目还保留了原始 Mac 启动脚本和说明，可作为辅助。

## 3. Python 依赖

由 `requirements.txt` 管理：

- `fastapi`：HTTP/WebSocket 后端。
- `uvicorn`：ASGI 服务。
- `requests`：同步 HTTP 请求与部分文件下载。
- `httpx`：异步 HTTP、流式请求和长任务。
- `pydantic`：请求/响应数据模型。
- `python-multipart`：文件与表单上传。
- `pillow`：图片尺寸、格式、裁切、预览转换。
- `numpy`：本地抠图的模型张量和透明遮罩处理。
- `onnxruntime-gpu[cuda,cudnn]`：BRIA RMBG-2.0 的 CUDA 优先推理；没有可用 GPU 时保留 CPU 回退能力。

Windows 版默认在小美画布服务内直接运行 `BRIA RMBG-2.0` ONNX 模型，不再打开外部抠图软件。首次点击“去背景”时下载约 1.02 GB 的模型到 `data/models/background-removal/`，下载过程显示进度，并校验文件大小与 SHA-256；原图不会上传第三方，也不会被覆盖。

默认优先使用 `CUDAExecutionProvider`（当前电脑为 NVIDIA GeForce RTX 4060）；如果 CUDA/cuDNN 会话或显存不可用，后端会明确记录并回退 `CPUExecutionProvider`，界面不会把 CPU 伪装成 GPU。设备状态可从 `GET /api/background-removal/status` 查看。

如需使用轻量模型，可显式选择已下载的 `birefnet-general-lite`；`ben2-base` 仅作为旧版兼容选项。若只使用在线生图，服务启动时不会加载抠图模型，首次使用才初始化 ONNX Runtime。

标准库还使用 `asyncio`、`subprocess`、`zipfile`、`hashlib`、`hmac`、`urllib`、`tempfile`、`mimetypes`、`xml.etree` 等。

### 跨境页面翻译（可选）

亚马逊入口会在内嵌会话首次打开亚马逊页面时自动协商简体中文，并使用亚马逊自己的语言偏好；因此支持中文的亚马逊页面无需先启动翻译服务。其他跨境平台仍以平台自身返回的语言为准。

跨境平台工具栏的“翻译中文”按钮使用本机 LibreTranslate 的 `/translate` 接口，将当前已加载页面中的可见外文翻译成中文。它不处理输入框、密码框和可编辑内容；未启动翻译服务不影响小美画布的其他功能，点击按钮时会明确提示先启动本机服务。

LibreTranslate 是开源、自托管的机器翻译 API，底层使用 Argos Translate。Windows 可先安装 Docker Desktop，再在 PowerShell 单独启动本机服务：

```powershell
docker run --rm -p 5000:5000 libretranslate/libretranslate
```

如果已经用 Python 安装 LibreTranslate，也可以直接运行：

```powershell
python -m pip install libretranslate
libretranslate
```

默认地址是 `http://127.0.0.1:5000/translate`，通常不需要额外配置。若地址不同，可在 `API/.env` 设置 `XIAOMEI_TRANSLATE_URL`；若本机服务启用了 API Key，再设置 `XIAOMEI_TRANSLATE_API_KEY`。修改后重启桌面端。页面文字较多时按钮会先翻译已加载的部分文字；再次点击可恢复原文。

项目采用本机地址限制，避免把平台页面内容默认发送到外部翻译服务。服务安装、模型包和运行数据均不写入项目源码包。

商品分析台的淘宝/天猫可见页面采集推荐安装 Node.js 18+ 和 Playwright：

```powershell
cd tools\commerce-analysis
npm install
```

未安装 Playwright 时仍会回退到项目内置的 Node CDP 采集器；两种方式都要求本机存在 Edge，并且只读取用户手动登录后的可见页面。

安装脚本位于 `CLI/`、`tools/` 和项目根目录。

画布右侧 Agent 的复杂任务可选启用 Codex Harness。它复用现有 `canvas-llm` 做视觉理解和结构化计划，再通过本机 `codex app-server` 调用画布动态工具；不会把 API Key 写入源码。首次使用前请确认：

```powershell
codex --version
codex login
```

Harness 状态可通过 `GET /api/canvas-agent/runtime-config` 查看。设置 `XIAOMEI_CODEX_HARNESS=0` 可关闭自动接管，恢复原有 Agent/计划模式；运行记录保存在 `data/canvas_agent_runs.json`，属于运行数据，不应打入发布包。

## 5. 目录权限

服务需要对以下位置具有读写权限：

- `API/`
- `data/`
- `assets/`
- `output/`
- `logs/`
- `history.json`

不要安装到只读的系统目录。Windows 中文路径已被支持，但路径过长时建议放在桌面或磁盘根目录附近。

## 6. 网络和防火墙

- 本机访问使用 `127.0.0.1:3000`。
- `main.py` 监听 `0.0.0.0`，局域网开放前应自行增加认证、反向代理与防火墙策略。
- 项目当前适合单用户本地使用，不应原样暴露到公网。

2. 在线生图模型列表随平台配置变化。
3. 生成过程显示任务进度，失败任务保留错误信息。

## 9. GitHub Releases 桌面版更新

桌面端会从 `desktop/update-config.json` 配置的 GitHub 仓库读取 Release。默认仓库是 `jkjk-8614/xiaomei`，软件会按当前平台和架构选择资产，并校验版本、文件大小和 SHA-256。更新只替换程序文件；用户数据位于 `%LOCALAPPDATA%\小美画布-测试版`（macOS 为用户的 Application Support 目录），不会随安装包覆盖。

每个 Release 应至少包含：

- Windows：`xiaomei-canvas-版本-Setup-x64.exe`。
- macOS：`xiaomei-canvas-版本-macOS-x64.zip` 和/或 `macOS-arm64.zip`。
- `update.json`：由发布脚本生成，记录各资产的下载地址、大小和 SHA-256。

仓库内的 `.github/workflows/desktop-release.yml` 会在推送 `v*` 标签时分别在 Windows 和 macOS 构建安装包，并只把 Windows Setup、macOS ZIP 和 `update.json` 发布到同一个 GitHub Release。macOS 用户下载校验后的 ZIP 后会打开压缩包位置，用户把新 App 拖到“应用程序”文件夹即可完成替换；Windows Setup 会自动启动安装并重启应用。Portable 版不参与软件内自动安装更新。

发布步骤：

1. 同步根目录 `package.json` 和 `desktop/package.json` 的版本号，例如 `0.1.0` 或 `0.1.0-test.4`。
2. 提交代码并推送标签：`git tag v0.1.0-test.6`、`git push origin v0.1.0-test.6`。
3. GitHub Actions 完成后，在 Release 页面确认只有 Windows Setup、macOS ZIP 和 `update.json`，再把 Release 设为公开可下载。
4. 用户从旧版侧栏点击“检查更新”，或等待启动后的后台检查。

如果需要指定测试 Release，可在 `desktop/update-config.json` 的 `github.releaseTag` 填入标签；也可以用 `XIAOMEI_UPDATE_GITHUB_TAG` 临时覆盖。旧的公网清单方式仍兼容：设置 `provider` 为 `manifest` 并提供 `manifestUrl`，地址必须是 HTTPS。
