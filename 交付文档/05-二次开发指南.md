# 二次开发指南

## 1. 开发环境

项目不需要前端编译。修改文件、重启后端（仅后端改动需要）并强制刷新浏览器即可。

推荐：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

前端修改后使用 `Ctrl + F5`。若仍加载旧文件，更新引用 URL 上的 `?v=` 参数。

### 调整 GPT 对话与 Skill

- 页面与交互：`static/gpt-chat.html`
- Skill 数据：`data/agent_skills/packages/<slug>/`、`data/agent_skills/package-index.json`（其中的 `categories` 保存自定义分类），以及兼容的 `data/agent_skills/*.md`
- 包接口：`POST /api/agent-skills/inspect-package`、`POST /api/agent-skills/inspect-upload`、`POST /api/agent-skills/import-package`、`PATCH /api/agent-skills/{skill_id}`、`GET /api/agent-skills/{skill_id}/resource`；分类接口为 `GET/POST /api/agent-skills/categories`、`PATCH/DELETE /api/agent-skills/categories/{category_id}`。GPT 与画布共用“选择文件夹 → 自动检查 → 导入”单按钮流程；扫描器同时接受带 `manifest.json` 的批量包和包含 `SKILL.md` 的标准单 Skill 目录。
- 导入后必须调用 `GET /api/agent-skills` 的 `no-store` 列表刷新并保留原列表作为失败回退；导入成功只更新库和详情，不自动设置当前对话 Skill。重复内容返回 skipped，冲突返回 conflicts，由前端在确认后重试 `replace=true`。
- 基础接口：`GET /api/agent-skills`、`GET /api/agent-skills/{skill_id}`、`POST /api/agent-skills/create`
- `SKILL.md` 正文和其中明确引用的文本 `references` 由 `build_agent_skill_context()` 组装，受 `AGENT_SKILL_CONTEXT_MAX_CHARS` 限制；脚本、CLI、第三方依赖和授权只登记状态，不在宿主内执行。
- 对话请求通过 `ChatRequest.skill_id` 复用同一份 Skill 指令；修改注入逻辑时要同时回归普通、流式和 Agent 三种模式，并检查 GPT/画布共享选择键 `xiaomei_agent_skill_selection_v1`。
- 商品分析台的 `static/js/commerce-analysis.js` 与 `static/gpt-chat.html` 共用 `gpt_chat_browser_user`、`gpt_chat_last_conversation_v1` 和 `/api/conversations`。修改任一侧的会话接口、用户标识或消息保存逻辑时，必须同时回归 AI 助手跳转、历史列表、新建会话和跨页面同步。

- Agent 计划模式：`static/js/canvas-agent.js`、`static/smart-canvas.html`、`static/css/smart-canvas.css`；后端结构化计划入口为 `POST /api/canvas-plan`。画布 Agent/计划请求通过 `skill_id` 由后端确认并注入 Skill 上下文，生成节点的 `runSettings.agentSkillId/agentSkillName` 会随在线生图请求保留。
- 持久化 Agent 节点的 Skill 库由 `agentSkillLibraryHtml()` 和 `bindAgentNodeControls()` 负责搜索、调用与节点滚轮隔离；“管理”按钮应继续复用 `#canvasAgentSkillPopover`，不要另建第二套 Skill 管理库。
- 后端任务：`/api/canvas-image-tasks`、`/api/canvas-comfy-tasks`、`/api/canvases/*`
- 画布分享入口在 `static/js/canvas-list.js` 的卡片菜单；后端分享接口为 `POST /api/canvases/{id}/shares`、`GET /api/canvases/{id}/shares`、`POST /api/canvas-shares/{share_id}/revoke` 和 `/share/{share_id}`。局域网请求直接进入主端口，互联网请求由 `CanvasShareGateway` 代理到临时 cloudflared 端口；网关默认不暴露主应用 API，仅额外放行可编辑链接所需的图片派生上传、去背景模型状态/处理和素材打包下载，并且每个媒体地址仍须属于分享范围。

### 调整图片空间

- 页面入口：`static/asset-manager.html` + `static/js/asset-manager.js` + `static/css/asset-manager.css`
- 后端目录设置：`main.py` 中 `IMAGE_SPACE_FOLDER_NAMES`、`/api/storage-settings` 和 `/api/storage-files`
- 统一目录结构为“图片空间/上传素材、生成素材、本地素材”。旧目录通过 `legacy_dirs` 兼容读取；迁移时不覆盖目标同名文件。
- `/api/storage-files` 的生成目录列表同时枚举图片和视频，并返回媒体类型数量；生成素材页提供“全部生成 / 图片 / 视频”渠道，复用 `assetKind()`、`assetThumb()` 和灯箱预览处理视频，图片资产库导入仍只接受图片。

### 调整统一素材索引与回收站

- 索引实现位于 `asset_registry.py`；`main.py` 通过 `asset_registry_register_media()` 统一登记新媒体，并通过 `asset_registry_bind_canvas_refs()`、`asset_registry_register_history_record()` 为兼容数据补齐引用 ID。
- 对外查询和维护接口为 `/api/assets`、`/api/assets/index`、`/api/assets/{asset_id}`、`/api/assets/{asset_id}/references`、`/api/assets/trash` 以及对应的移入回收站、恢复和彻底删除操作。旧文件只应被索引，不应在维护脚本中直接搬迁。
- 新的画布、历史或素材库字段必须优先保留既有 `asset_ref_id`，同时继续保留可用的 `url`/路径作为兼容回退。不要用一次读取重新生成 ID，也不要把上游提供的 `asset_id` 当作本地素材引用 ID。
- 删除本地媒体不得直接调用 `os.remove()` 或递归删除目录；先检查 `asset_registry_references()`，再使用统一回收站辅助函数，使恢复位置和随附元数据保持一致。

## 3. iframe 通信

主壳和功能页通过 `window.postMessage` 同步：

- 主题、语言、UI 缩放和皮肤；
- API 平台或工作流变化；
- 历史预览打开/关闭；
- 页面聚焦刷新。

新增消息时：

1. 使用明确的 `type`。
2. 主界面检查 `event.origin`。
3. 不在消息中传 Key。
4. 同时处理 iframe 尚未加载的情况。

## 4. 后端修改策略

`main.py` 是大文件，推荐步骤：

1. 搜索路由装饰器定位入口。
2. 搜索前端 URL，确认所有调用方。
3. 搜索请求模型类和同名辅助函数。
4. 先增加兼容字段，避免删除旧字段。
5. 对响应结构做 URL/base64/任务 ID 多形态兼容。
6. 失败时返回可显示的错误信息，不吞异常、不无限转圈。

## 5. 新增页面

1. 在 `static/` 新建 HTML、CSS、JS。
2. 在 `index.html` 的 `.stage` 添加 iframe。
3. 加入允许的页面 ID、侧栏入口和状态恢复逻辑。
4. 接入主题、语言、缩放消息。
5. 更新缓存版本和文档。

## 6. 新增设置项

- 用户界面偏好可放 `localStorage`，应提供稳定键名和默认值。
- 跨浏览器/跨设备必须保留的设置放后端 JSON。
- 绝对路径、Key 和个人目录不得写入源码默认值。
- 页面启动时应先读取旧值，不要每次登录恢复成 1:1 等硬编码默认值。

## 6.1 小美画布多人协作

- 智能画布通过 `/ws/canvas-collab/{canvas_id}` 建立在线成员、彩色光标、节点选择和编辑锁通道；连接只覆盖当前分享范围，断开或心跳超时会自动释放锁。
- `PATCH /api/canvases/{canvas_id}/nodes` 只提交变化的节点、删除项和必要的画布元数据。节点保存 `_collab_updated_at` 版本；同一节点发生并发更新时返回 `409`，前端显示本地/对方两个版本供选择。
- 分享记录支持 `scope=canvas|project`、`role=editor|viewer` 和 `allow_assets`。项目级分享允许同一项目内的画布访问；关闭素材引用时，分享网关仍可读取节点结构，但拒绝画布媒体 URL。
- 分享者是运行桌面端服务器的本机；主持人可以在协作面板查看在线成员并移出成员。不要把协作 token、成员身份或运行数据写入源码包。

## 7. 图片与任务原则

- 生成中显示明确进度；无法获得真实百分比时标记为估算。
- 失败任务必须保留错误状态和重试入口。
- 多图响应不能只取前三张；遍历所有返回图片容器。
- 扩图底图留白使用透明像素；拖动单侧控制点时，提交尺寸不得保留初始预览在其他边的默认留白。生成结果必须按 `outpaintPreserve` 在上游原始结果中的坐标锁定中心区域，再减去裁切偏移；不得按裁切后的尺寸重新缩放原图。该上下文必须随单次请求的 `outpaint_mode` 显式传递，不能保存到节点、全局或最近设置；后端落盘与前端旧任务兜底都要使用同一套窄幅羽化过渡。
- 单屏重生成必须替换目标屏，不追加旧图。
- 历史预览使用原媒体 URL，不使用缩略图 URL；图片按原像素范围缩放，视频使用原生播放控件。历史图片拖到画布继续使用原图，拖到外部应用时由 `static/history.html` 生成压缩导出副本。
- 缩放不得无上限超过原图像素，避免文字发糊。

## 8. 商品分析工作台

商品分析页面为 `static/commerce-analysis.html`，前端通过 `POST /api/commerce-analysis/jobs` 创建任务并轮询 `GET /api/commerce-analysis/jobs/{id}`；旧客户端仍兼容 `POST /api/commerce-analysis/fetch`。使用方式是：粘贴淘宝/天猫/1688 商品链接，点击“开始分析”，再查看概览、用户评价、主图诊断、详情页、问大家、SKU/规格和分析报告。

- 桌面版地址栏打开淘宝/天猫/1688 商品详情页后，Electron 通过 `did-finish-load` 通知前端，前端自动读取商品基础信息、主图、详情、SKU 和视频，并保留评价/问大家数量；详情模块只读取当前已挂载的详情 DOM、懒加载属性、初始化状态和页面打开期间捕获的 `detail.getdesc` 响应，不点击详情标签、不调用 `scrollIntoView`/`window.scrollBy`，因此打开商品链接和点击“详情页长图”都不会改变商品页位置。详情图片 URL 直接交给后端下载并拼接 PNG，资源卡完成后可打开纵向预览或下载。用户点击“用户评价”或“问大家”资源卡后才启动对应的可见操作：读取基础商品状态，点击目标入口并滚动采集正文。快捷分析“分析评价和问大家”会把两个模块作为一次组合采集任务，等待两类样本准备好后自动发起分析。进度通过 `commerce:collection-progress` 更新右侧状态，商品视图同步显示“智能体正在操作”边框、图标动画和“停止”按钮。切换到同一商品或追踪参数变化不会重复创建任务，重复请求也不会清掉正在运行的采集锁；主窗口失焦或最小化时关闭页面后台节流，并对鼠标/滚轮动作提供同一白名单目标的页面内回退，手动“开始分析”仍可用。淘宝/天猫使用 `persist:xiaomei-commerce`，1688 使用 `persist:xiaomei-1688`，千牛/生意参谋使用 `persist:xiaomei-qianniu`，三组会话不会互相覆盖。
- Electron 商品页始终只走这一条可见采集链：成功快照通过 `/api/commerce-analysis/import` 进入统一合同，失败时只显示真实的 `login_required`、`verification_required` 或失败原因，不再回退创建第二个 FastAPI 商品任务。相同商品、相同桌面标签页的短时间登录/验证导入会复用已有失败结果；成功数据、深度模块和不同标签页仍然独立，既不跨商品串数据，也不删除历史记录。
- 如果没有 Electron 商品页桥接，打开链接后才会创建后端浏览器采集任务；浏览器兼容路径与桌面路径共用资源卡和结果合同，但不会互相降级或并发。
- 经营助手不得新建聊天页或再次采集商品。它复用 `/api/chat/stream` 的 `mode=merchant-agent`，并只通过服务端工具读取本次会话关联的商品任务。工具轮次上限为 6，每轮最多 4 个读取工具；新增工具时必须保留任务/资源范围检查、读取后才能暂存变更，以及证据 ID 的服务端生成。
- `merchant_changes` 的状态机固定为 `pending → approved → applied`，也可从待确认/已批准进入 `discarded`；聊天文本没有批准能力。变更接口为 `GET /api/merchant-agent/changes`、`GET /api/merchant-agent/changes/{id}`、`POST /approve`、`POST /apply` 和 `POST /discard`。应用时必须复算商品快照摘要，摘要不同则清除旧批准并要求重新暂存。
- 跨页交接只传 `merchant-change-handoff` 的 `change_id`。`static/index.html` 负责切换到 `commerce` iframe，`static/js/commerce.js` 再获取已应用账本项；不要把方案正文写进 `localStorage` 或通过 `postMessage` 传递。`generation_batch` 使用账本给出的幂等键并限制最多 20 个工作台任务，仍由用户在工作台点击开始生成。

- 如需先登录淘宝，点击“登录淘宝”。`POST /api/commerce-analysis/browser/login` 只会打开项目专用、可见 Edge 中的淘宝官方登录页；不接收账号、密码或验证码。`GET /api/commerce-analysis/browser/session` 只返回浏览器连接/登录页状态，不应扩展为返回 Cookie、账号或网页正文。
- 专用 Edge 使用 `data/commerce_analysis_browser_profile/` 作为本地运行数据。商品分析任务在检测到该 Edge 已打开时会优先复用其中的会话；关闭窗口后会话仍由该本地目录按浏览器规则保存。该目录与快照、SQLite 一样不得打入发布源码包。Electron 桌面版的淘宝/天猫、1688 与千牛/生意参谋分别使用 `persist:xiaomei-commerce`、`persist:xiaomei-1688` 和 `persist:xiaomei-qianniu` 三个内嵌会话。
- 运营报表独立采集使用 `POST /api/commerce-analysis/reports/capture`：`kind=operations` 生成“商品运营数据 - 最近30天”结构，`kind=audience` 生成“商品人群结构数据 - 最近30天”结构。桌面壳只读取当前千牛/生意参谋可见表格，或通过用户主动选择的官方 CSV/JSON 文件导入；若业务方已有官方授权接口，可把已授权返回的 `recent30` 结构以 `source=authorized-api` 提交到同一接口。后端按达笔字段分段、分组和百分比格式输出，缺失字段留空，不代持接口令牌，也不调用达笔私有服务。

- 普通公开页面先由后端读取 HTML、JSON-LD、页面图片和可见文字。
- 淘宝/天猫返回登录页时，后端会按需启动可见 Edge 窗口；用户手动完成登录后，Playwright 采集器保留原始链接并清理广告追踪参数，直接读取新版页面初始化状态，并按达笔固定入口触发目标 mtop 接口：评价优先读取 `rateList`，问大家优先读取 `questionList`。如果问大家正文已预载入但没有可回读响应，Electron 和 Playwright 都只从点击后打开的问大家抽屉可见问答卡精确兜底，不扫描整页文字。Electron 路径使用 `desktop/dabi-agent.cjs` 执行截图、CDP 鼠标点击和滚轮；模块不完整时保持 `partial`/`missing`，不再启用会混入页面文字的旧多轮 DOM 扫描。
- 商品资源卡的结构化数据下载接口仍返回 CSV；`images`、`detail_more`、`sku_images`、`videos` 使用 `/api/commerce-analysis/jobs/{id}/resources/{resource_id}/media` 下载实际媒体 ZIP，`detail` 使用同一媒体接口生成详情页纵向长图 PNG。详情页长图资源卡已按达笔交互改为直接打开纵向滚动预览，同时保留卡片下载入口；预览层仍提供下载。需要内嵌图片时使用 `?preview=1` 请求 `inline` 响应。媒体 CDN 的签名查询参数必须保留到下载请求，不应再次按普通页面链接清洗。
- 商品信息基础状态由 `tools/commerce-analysis/product-page-state.cjs` 统一提供给 Electron 与 Playwright，解析类目、价格区间、核心/详细参数和品牌；商品信息另有 `/resources/product.txt` 达笔兼容导出。SKU 组合必须带真实 ID 和规格路径，不能从当前选中项或尺码表推导。
- 可见 Edge 检测到登录、扫码或页面验证时不会立即退出，达笔式采集默认最多保留 90 秒等待人工操作；`COMMERCE_ANALYSIS_FAST_BROWSER` 只影响等待预算，不再切换到旧的宽泛 DOM 样本路径。桌面 Electron 的可见操作滚动次数可通过 `XIAOMEI_DABI_VISIBLE_SCROLL_PASSES` 调整，默认 40 次；超时后 Edge 窗口仍保留，完成操作后点击重试即可复用登录会话。
- 返回结构中 `product` 会稳定提供 `title`、`thumbnail`、`id`、`category`、`store`、`brand`、`priceMin`、`priceMax`、`priceRange`、`sales`、`reviewCount`、`questionCount`、`skuCount`、`coreParams` 和 `detailParams`；`mainImages`/`images` 是最多 5 张主图，`detail.images`/`detailImages` 是详情图片，`sku` 保存规格组和可拆分的 SKU 组合；旧版导入结果仍兼容 `images` 字段。若商品标签暂时跳转到官方登录/验证页，前端保留原商品 ID 和聊天上下文，回到商品详情页并完成加载后自动重试；只有商品 ID 而没有实际字段时不显示“已读取商品”，而显示待登录/验证状态。
- 浏览器采集使用项目现有 Node.js + Playwright，优先连接或启动可见 Edge，并保留 Node.js WebSocket/CDP 兼容采集器；不新增 Python/npm 依赖，需要本机安装 Node.js 和 Microsoft Edge。
- 画布 `dabi-browser` 与商品分析台共用现有 Playwright 依赖，但使用不同的用户目录：`data/browser_agent_profile/` 只保存通用网页助手会话，`data/commerce_analysis_browser_profile/` 继续只保存商品分析台会话；两个目录都属于运行数据。
- 采集器不会绕过验证码、滑块或风控。浏览器会使用 `data/commerce_analysis_browser_profile` 保存登录会话，属于运行数据，不应打包发布。
- 评价正文默认最多整理 200 条，支持通过 `COMMERCE_ANALYSIS_MAX_REVIEW_SAMPLES` 或 `XIAOMEI_DABI_MAX_REVIEW_SAMPLES` 调整（最高 5000）；页面显示的 `totalCount` 仍表示平台总量，不等于本次真实样本数。
- 没有 Node.js/Edge 或页面仍要求验证时，可以在“导入结果”导入外部浏览器/Playwright 整理出的 JSON；未返回的模块保持为空，不用演示数据补齐。
- 评价与问大家快照必须绑定 `productId`、`normalizedUrl`、`collectedAt` 和独立 `moduleStatus`。模块状态中的 `totalCount` 只表示页面/接口报告的总量，`sampleCount` 是规范化后展示的条数，`realResponseSampleCount` 是该模块真实响应中保留下来的样本数，`responseCount` 是捕获到的对应响应数；两类样本均保留 `sourceStepIds`、`sourceSteps` 和 `evidenceIds`，不能从另一个商品或另一个模块补齐。
- 每个任务都可通过 `GET /api/commerce-analysis/jobs/{id}/verification.json` 或 `GET /api/commerce-analysis/jobs/{id}/verification.csv` 下载核验清单。清单只包含身份、时间、状态、计数、来源步骤、证据定位和缺失原因，不保存 Cookie、Token、请求/响应头或原始响应正文。
- 评价优先接受 `rateList`/对应真实响应，问大家优先接受 `questionList`/对应真实响应；若问大家页面已显示真实问答卡但接口没有可回读响应，则使用已打开抽屉内的精确可见卡作为页面兜底，并记录 `dabi-visible-question` 来源；只有页面总量而没有正文时显示 `partial`/`deferred`/`missing` 及原因，资源卡明确显示“点击采集正文”“需登录/验证”或“采集失败，点击重试”，前端明确写出“未使用演示数据”。用户在输入框手动输入 `@主图`、`@详情页长图` 等资源名时，会和资源选择器一样转成当前商品的 `link_resource_ids`。重试或切换商品时会先比较商品 ID/规范化链接，身份不一致则丢弃旧模块，禁止串入上一商品。

## 9. 右侧 Agent 与 Codex Harness

复杂任务的执行链路为：

1. 前端保留正式任务范围、参考图和商品链接任务 ID。
2. `POST /api/canvas-agent/orchestrate` 先调用现有 `canvas_plan`/`canvas_llm`，生成结构化计划。
3. 后端启动短生命周期 `codex app-server`，以 `dynamicTools` 注入 `xiaomei_*` 画布工具；工具只返回待执行操作，不直接维护第二份画布图谱。
4. 前端轮询 `GET /api/canvas-agent/runs/{run_id}`，把分析、计划、工具调用、审批和完成事件显示在 Agent 面板。
5. 普通工作流复用 `canvas-agent.js` 的 `executePlanOption`，因此正式连线、撤销、分阶段生图和任务轮询保持一致。

工具边界：读取画布、读取素材库、读取商品快照和查询任务为只读；创建节点、连线和单张生图可登记为待执行操作；删除节点、网页提交/发布/购买、批量生图必须经过 `/approve` 端点确认。`POST /api/canvas-agent/runs/{run_id}/interrupt` 可停止当前 Harness。

Codex CLI 不可用、未登录或通过 `XIAOMEI_CODEX_HARNESS=0` 关闭时，接口返回 `fallback`，前端自动回到原有 Agent/计划链路。不要把 Codex 登录信息或任何 API Key 写入 `main.py`、文档或前端 localStorage。
