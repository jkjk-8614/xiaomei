# 商品模板采集

本流程只用于用户明确要求采集商品模板，或标准上架缺少可用模板。不要与标准上架步骤混用。

## 启动采集

1. 引导或启动采集前，同一轮说一次：“采集商品模板是为了识别该类目的必填属性和规格规则，没有模板就无法准确、安全地完成上架。”即使用户已经提供商品 ID 也不能省略。
2. 用户未提供商品 ID 时，只问：“提供一个已登录的千牛后台中已有的同类目商品ID。”不要同时追问平台、类目或发布页入口；不要要求商品必须位于仓库。
3. 用户提供商品 ID 后，无论快速模式还是严格模式，都把这次输入视为采集授权并直接继续。不要再次确认，不要提醒采集会影响原商品。
4. 调用 `taobao_launch_learn_template({ itemId })`。已经明确平台时可附带 `platform`；不要为了平台单独打断用户。
5. 工具成功后只简短说“已启动采集”，然后立即结束当前回合。此后不得再调用任何工具，禁止用 exec/process/sleep、定时器、重复查模板或其他轮询方式原地等待。

桌面端会打开该商品预填编辑页，挂上采集监听，并自动滚到底部点击真实“提交宝贝信息”。如果页面停在登录页或触发风控滑块，提示用户先完成登录/验证，再重试。

## 收到成功信号

仅在后续新收到桌面端的 `[收到模板采集成功信号]` 时开始新的处理回合。该信号只负责唤醒当前会话,不是模板已保存的最终依据。

收到信号后不得直接回复采集成功，必须先复核本地模板：

- 已知类目和平台：调用 `taobao_launch_template_list({ catIds: [catId], platform })`，只接受类目、平台匹配、`status=valid`，且 `createdAt` 在收到信号时最近约 5 分钟内的最新模板。
- 不知道类目或平台：调用 `taobao_launch_template_list({})`。只有最近约 5 分钟内恰好一份模板能与本次上下文一致时通过；多份无法区分时不得猜。
- 复核到本次新模板后，必须先生成简短语义名并调用 `taobao_launch_template_manage({action:"name-after-capture",templateId,semanticName})`。`semanticName` 使用“叶子类目-主要区别”：优先把 `skuDimensions` 合并为主要区别；没有 SKU 维度时使用“单规格”；`categoryPath` 缺失时使用“类目<catId>”，不得猜类目名称。只使用中文且不超过 20 个字符，不包含平台、店铺、日期、时间、序号或“模板”。日期 `_YYYY_MM_DD` 和同日重名序号 `_2/_3` 由工具添加。
- 复核通过后再回看原始意图：原任务是上架就使用新模板继续；原任务只是采集就报告成功并结束。
- 报告采集结果时必须同时显示类目名称和类目 ID。优先使用 `template_list` 返回的 `categoryPath`（至少取末级名称）；如果 `categoryPath` 缺失，明确说明类目名称暂不可用，不得猜测。
- 同时显示工具返回的最终模板名称，并告诉用户可以直接要求修改；不要为了名称再阻塞式追问。
- 复核失败时不得继续上架，也不得把已有模板当成本次结果。说明“收到采集信号，但没有确认到本次保存的模板”，让用户重试或检查模板。
- 复核只证明模板已保存，不代表通过 Preview，后续仍必须走完整安全链路。

失败或结果未知不会覆盖已有模板。自动模式通常无需 `taobao_launch_finish_template_learning`；只有用户明确要求停止或工具要求关闭监听时才调用。
