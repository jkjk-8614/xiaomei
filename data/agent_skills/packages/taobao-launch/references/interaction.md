# 模式、用户语言与进度

## 上架模式

- **快速模式（默认）**：用户未明确指定模式时使用。唯一确定的发布渠道、类目和商品模板直接采用；用户输入商品 ID 后直接采集；单商品 Preview 通过并原样展示后立即提交，不等待确认。
- **严格模式**：仅当用户明确说“严格模式 / 严格上架”时使用。在发布渠道和单商品上架 Preview 两个关键节点等待用户明确确认；其余唯一确定步骤直接继续。
- 模式只作用于当前任务，不是永久偏好。中途切换从下一处未执行的确认节点生效；已经提交或已触发的采集不能撤回。
- 两种模式都不能跳过登录、模板、属性、SKU、主图、Preview、风控和 unknown 等硬门。

具体上架任务开场总览后提示一次当前模式，不等待回复：

- 快速模式：“当前使用快速模式，可随时说‘切换严格模式’来逐步确认。”
- 严格模式：“当前使用严格模式，会在发布渠道和上架预览时请你确认。”

## 用户语言

用户是不懂内部实现的普通商家，全程使用大白话中文：

- 始终用中文回复，包括思考过程
- 不说工具名，使用“检查登录”“整理商品资料”“预览”“正在提交”等业务表达。
- 不说 `payload`、`confirmToken`、`prompt`、`item_msg`、`catProp`、`propsDir`、`pic_dict`、`sku_list` 等字段名。
- 不展示令牌、绝对路径、原始 JSON 或英文报错。
- 不旁白内部推理或参数传递。
- 用户只需看到开场总览、短进度、预览清单和最终结果。

## 四阶段进度

开场只发一次总览：

> 好的,这就帮你上架。整个过程分 4 步:**① 核对店铺和类目 → ② 整理商品资料 → ③ 校验预览 → ④ 正式上架**。开始 👇
>
> 当前使用快速模式,可随时说“切换严格模式”。

四个大步骤固定为：

1. **① 核对店铺和类目**：登录、平台、类目和商品模板。
2. **② 整理商品资料**：素材、属性、SKU、尺码表和草稿。
3. **③ 校验预览**：Preview 硬校验和预览展示。
4. **④ 正式上架**：提交、轮询和商品链接。

格式：

- 每个大步骤开始时，只换行输出一次加粗标题，例如 `**② 整理商品资料**`，独占一行，独占一行。
- 小步骤各占一行，例如 `- 正在整理规格和价格,请稍等...` 或 `- SKU 已整理好:32 个组合`。
- 一直在当前大步骤下追加短进度，切换大步骤时才输出下一个标题。
- 不使用反复重绘的固定勾选清单。
- 成段内容只用于工具返回的 Preview 和最终结果。

整理 SKU、生成草稿、提交上架等耗时步骤开始前，必须先发一条短进度。组装草稿 / Preview 前可说“正在整理商品资料,大约需要 2 到 3 分钟”。提交前固定使用“正在提交到淘宝...”或对应平台，禁止使用中文双省略号。
