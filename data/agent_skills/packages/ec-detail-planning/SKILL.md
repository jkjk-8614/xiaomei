# 电商详情页脚本与逐屏生图

这个 skill 用于把用户提供的产品图和产品名称转成中文电商详情页脚本，再通过 `当前宿主工具` 按“一屏一图、`maxInFlight = 5`”有界并发生成图片。它也是分析 skill 之后的第二阶段：读取分析报告或 `生成用策划摘要`，再结合产品图和产品名称完成类目翻译。

## 输入要求

- 产品图：必填，支持 1-4 张。
- 产品名称：必填。
- 目标人群：选填。
- 卖点：选填。
- 需要的屏数：选填；交给详情页脚本提示词处理默认值和 7-12 屏限制。
- 备注：选填。
- 参考分析报告：选填，通常是当前工作区 `reports/ec-detail-analysis` 下由 `$ec-detail-analysis` 保存的 Markdown 报告，也可以是用户提供的其他 Markdown 报告路径。
- 竞品分析摘要 / 生成用策划摘要：选填，可以是用户直接粘贴的 `## 生成用策划摘要` 内容。

产品图不需要在分析阶段提前上传，但在本生成阶段是必填项。如果缺少产品图或产品名称，先让用户补充缺失的必填信息，不要继续生成脚本。用户上传 1-4 张产品图时，后续生图阶段每一屏都使用全部产品图作为参考图；如果用户上传超过 4 张，只使用前 4 张，并明确告诉用户超出的图片不会参与本次生图，不要静默丢弃。

## 用户流程

1. 用户上传产品图并填写产品名称后，直接在对话中输出完整详情页脚本；目标人群、卖点、屏数和备注没有填写时按本技能默认规则处理，不追问可选信息。
2. 用户确认脚本后，直接使用当前用户附件的原始路径上传并逐屏生图；不检查文件、不搜索目录、不翻译或重写文件名。
3. 上传或生图失败时，原样报告错误并停止当前流程，不自行换图、换路径或新建宿主工作区重试。

## 脚本阶段禁止操作

- 详情页脚本只在当前对话中展示并保留在会话上下文中。除非用户明确要求“保存”或“导出”，否则禁止调用 `write`、`edit` 或任何文件写入工具，禁止创建 `.md`、`.txt`、JSON、临时文件或其他脚本副本。
- 用户明确要求保存但没有指定目标路径时，先询问保存位置，不得自行选择工作区、桌面、临时目录或其他目录。
- 用户确认继续生图前，禁止读取 `EXECUTION.md`，禁止调用宿主工作区、上传、保存路径、生图和文件写入工具。
- 用户确认后，直接从当前会话中已展示的脚本提取总体视觉基调和逐屏内容，不得先把脚本保存到文件再读取。
- 脚本阶段唯一允许的输出是对话中的完整脚本和一句“请确认是否继续生图”。

## 信息使用优先级与保守推断

- 用户直接填写的字段优先级最高；用户粘贴的策划摘要其次；参考分析报告再次。
- 只要用户填写了“目标人群”“卖点”“备注”中的任意一项，或提供了报告/策划摘要，就直接使用已有明确信息。未填写且无法从已有内容提取的字段保持为空，不额外运行通用推断。
- 只有“目标人群”“卖点”“备注”“参考分析报告”“竞品分析摘要 / 生成用策划摘要”全部为空时，才根据产品图和产品名称在同一次策划推理中保守推断：
  - 识别核心购买人群、扩展人群、常见购买动机、使用场景和 4-6 个用户关注点。
  - 提炼 3-5 个核心卖点、3-5 个辅助卖点及表达优先级，每个卖点同时考虑用户价值和适合的视觉表达。
  - 推断必须具体、可执行，避免“年轻人”“大众用户”“品质好”“性价比高”等空泛表述。
  - 不编造参数、价格、销量、容量、材质结论、认证、检测、专利、品牌背书、功效承诺或活动信息；需要事实支撑时写“可结合真实信息补充”。
  - 将推断直接作为脚本策划上下文，不单独向用户输出中间分析，也不压缩成可能丢失信息的 40 字字段。

## 分析报告 / 策划摘要联动

- 如果用户提供 `参考分析报告` 路径，先读取该 Markdown 报告，并优先提取 `## 生成用策划摘要` 之后的字段。
- 为兼容历史报告，如果没有 `## 生成用策划摘要`，可以继续识别旧标题 `## 生成用 Brief`；这是兼容规则，新输出不要再使用英文 Brief。
- 如果用户直接粘贴 `生成用策划摘要` 或竞品分析摘要，优先使用用户粘贴内容；同时提供报告和粘贴策划摘要时，以粘贴内容为准。
- 将策划摘要映射到脚本策划输入：
  - `目标人群` 使用策划摘要的 `目标人群`。
  - `卖点` 合并策划摘要的 `主卖点`、`辅助卖点`、`核心购买动机` 和 `证据逻辑`。
  - `备注` 合并策划摘要的 `策划摘要类型`、`参考页面类型`、`参考页类目判断`、`我方产品信息`、`类目适配说明`、`生成阶段需补充`、`产品定位建议`、`首屏打法`、`视觉风格`、`画面语言`、`建议详情页结构`、`不建议照抄` 和 `生成备注`。
- 读取 `策划摘要类型` 并决定落地方式：
  - `通用打法型`：先根据产品图和产品名称识别我方类目，再把参考页打法翻译成我方详情页结构；不要照搬参考页类目卖点。
  - `类目翻译型`：直接使用已有类目适配说明，并结合产品图校准画面、卖点和证据。
  - `自家改版型`：按改版优先级重构脚本，优先修复分析报告指出的认知、欲望、信任、节奏问题。
- 如果 `参考页面类型` 是跨行业 Top、近邻类目或我方类目未知，生成脚本时只借鉴打法，不照搬参考页类目卖点；结合产品图和产品名称完成类目翻译。
- 策划摘要面向自家详情页生成，不能照搬竞品原文、竞品品牌名、竞品素材描述、竞品检测背书或竞品专属视觉皮肤。
- 如果报告里没有可识别的 `生成用策划摘要` 或旧标题 `生成用 Brief`，只使用报告中的明确分析结论作为辅助上下文，不要硬猜缺失字段。
- 即使提供报告或策划摘要，也仍然必须有产品图和产品名称；缺少任一必填项时，先让用户补充，不要生成脚本。

## 脚本策划流程

1. 确认当前消息包含产品图内容和产品名称；其余输入都是选填项，缺省时直接使用默认规则，不向用户追问。
2. 判断是否需要推断：
   - 如果提供了 `参考分析报告` 或 `竞品分析摘要 / 生成用策划摘要`，读取或整理策划摘要，先根据产品图和产品名称完成必要的类目翻译，再映射成目标人群、卖点和备注，完全跳过通用人群卖点推断。
   - 如果“目标人群”“卖点”“备注”“参考分析报告”“竞品分析摘要 / 生成用策划摘要”全部为空，按本文件的“信息使用优先级与保守推断”在同一次推理中完成推断。
   - 如果“目标人群”“卖点”“备注”中任意一项有用户输入，完全跳过推断。
3. 组合产品图、产品名称、用户输入、报告/策划摘要映射结果或推断结果、需要的屏数，作为详情页脚本策划输入。
4. 传给详情页脚本提示词前，始终把 `高端品牌感` 写入“备注”字段，并放在备注最前面：
   - 用户无备注，且未运行推断或推断备注为空：`备注：高端品牌感`
   - 用户有备注：`备注：高端品牌感，<用户备注>`
   - 使用推断提示词且推断出备注：`备注：高端品牌感，<推断备注>`
5. 按本文件的“详情页脚本生成规范”生成带 HTML 注释机器标记的 Markdown 详情页脚本，直接作为当前回复正文输出，不写入文件。
6. 把详情页脚本发给用户查看并请用户确认是否继续生图。用户确认前不得读取执行流程、创建宿主工作区、准备保存路径、上传产品图或写入脚本文件。不要询问生图尺寸/分辨率，生图尺寸固定使用 `2K`。生图比例默认使用 `9:16`；如果用户直接回复“确认”“可以”“继续”“生成”等确认语且未指定比例，就按 `9:16` 执行。用户主动指定其他支持比例时，才使用用户指定比例。

## 详情页脚本生成规范

输出一份中文 Markdown“详情页脚本策划方案”，用于明确总体视觉基调、单屏设计目的、画面内容和可直接上页面的文案。脚本必须方便用户阅读，也方便后续逐屏生图。

### 买家视角与内容边界

- 从买家的使用场景、情绪感受、实际需求、搭配方式、使用便利性和购买顾虑组织内容，重点回答“为什么需要、什么场景使用、如何融入生活、解决什么日常问题”。
- 不写成卖家产品说明书，不把参数、尺寸、规格、材质列表、洗涤说明或产品信息表作为独立屏幕。
- 用户明确要求展示真实参数时，只能作为正文或轻量说明补充；缺少真实信息时，用使用价值、生活场景或买家共鸣完成收束，不能用参数页凑屏数。
- 可以策划人物、道具、场景、微距、局部特写和互动内容，但必须保持产品主体、定位和目标用户感受一致。

### 总体视觉基调

必须使用以下固定结构和标记，标记原样输出且不放进代码块：

```md
<!-- VISUAL_TONE_START -->
### 一、总体视觉基调

#### 1. 风格定位
<整套详情页风格关键词>

#### 2. 色彩系统
- 主色调：
  - 色彩名称：
  - HEX参考：
  - 使用比例：
  - 适用位置：
  - 作用说明：
- 辅色调：
  - 色彩名称：
  - HEX参考：
  - 使用比例：
  - 适用位置：
  - 作用说明：
- 点缀色：
  - 色彩名称：
  - HEX参考：
  - 使用比例：
  - 适用位置：
  - 作用说明：

#### 3. 字体规则
- 标题：
  - 字体类型：
  - 字体气质：
  - 字重/层级：
  - 标题色值：
  - 使用场景：
- 正文：
  - 字体类型：
  - 字体气质：
  - 字重/层级：
  - 使用场景：
- 点缀/说明：
  - 字体类型：
  - 字体气质：
  - 字重/层级：
  - 使用场景：
  - 使用限制：

#### 4. 排版原则
<3-5 条适合移动端长图的排版原则>
<!-- VISUAL_TONE_END -->
```

- 色彩系统必须服务产品识别、目标人群和页面氛围，避免廉价、刺眼、杂乱的促销感。
- 标题色值必须给出一个确定的 HEX；字体规则要明确，不使用“或”“可选”“二选一”等要求用户继续选择的表达。
- 标题醒目、正文易读、点缀文字只做辅助；不需要点缀文字时写“不单独设置点缀/说明字体”。

### 单屏详情页脚本

总体视觉基调后输出 `### 二、单屏详情页脚本`。每屏必须使用成对机器标记，`index` 从 1 开始连续递增，开始和结束编号一致：

```md
<!-- SCREEN_START index="1" title="首屏主视觉" -->
#### 第1屏：首屏主视觉

- 设计目的：
<这一屏的转化任务>

- 画面内容：
<产品状态、视觉焦点、人物/道具、场景、情绪氛围、图文主次和背景氛围>

- 排版文案：
  - 标题：<8-14 字、可直接上页面的电商短句>
  - 正文：<不超过 2 句、可直接上页面的正文>
  - 点缀/说明：<确有必要时输出，否则省略>
<!-- SCREEN_END index="1" -->
```

- 页面主题用简短标题概括，例如首屏主视觉、核心卖点概览、材质细节、使用场景、设计亮点、多场景适配、使用价值总结、生活场景收束或买家共鸣收束。
- 每屏只聚焦一个主要任务。设计目的说明转化作用；画面内容说明产品主体、视觉焦点、素材和氛围，不写具体版式位置、单屏字号或单屏色值。
- 排版文案必须是可直接使用的文案，不写“建议标题为”“正文用于说明”等解释。标题建议 8-14 字，正文不超过 2 句，点缀说明不能抢占主信息。
- 屏幕顺序从第一印象、核心价值、细节证明、场景代入自然递进到买家共鸣。

### 输出硬规则

- 最终脚本使用 Markdown，直接输出在当前对话中，不包在代码块中，不附加无关解释，不保存为本地文件。
- 必须输出完整 `VISUAL_TONE_START/END` 和每屏 `SCREEN_START/END` 标记；标记不翻译、不改写、不省略、不嵌套。
- 屏数控制在 7-12 屏。用户未填写时默认 10 屏；低于 7 按 7，高于 12 按 12，不反复追问。
- 每屏固定包含“设计目的”“画面内容”“排版文案”；排版文案固定包含标题和正文，点缀/说明按需输出。
- 不使用“第一”“顶级”“最强”“永久”“100%”等绝对化表达。
- 不编造参数、容量、认证、价格、销量、材质结论、品牌背书或其他无法确认的信息。
- 不在脚本阶段生成图片。

## 生图提示词提取

用户确认继续生图后，为每一屏生成一个生图提示词：

```text
总体视觉基调：<完整总体视觉基调>。单屏详情页脚本：<当前屏完整脚本>
```

图片比例和生图尺寸不要写入生图提示词文本；比例只通过 `当前宿主工具 img2imgGpt` 的 `-r <比例>` 参数传递，尺寸固定通过 `-R 2K` 参数传递。

总体视觉基调提取、逐屏解析和全部单行提示词生成必须在一次连续推理中完成，不要拆成多次独立模型调用。直接从已确认的详情页脚本提取，不调用或生成解析脚本：

1. 取 `VISUAL_TONE_START/END` 之间的完整总体视觉基调。
2. 按 `SCREEN_START/END` 的 `index` 顺序逐屏提取完整单屏脚本。
3. 如果 HTML 注释缺失，才按“第N屏”Markdown 标题回退提取。
4. 为每屏拼接“总体视觉基调 + 当前屏完整脚本”。比例和分辨率单独记录，不写入提示词。
5. 每屏提示词直接生成为一条连续的单行字符串，不能包含换行符。总体视觉基调、标题、正文、卖点、画面内容、设计目的和视觉约束必须完整保留，不得摘要、润色、翻译或重排语义内容。

识别到屏幕后按编号建立正式生图队列并立即开始有界并发，不增加单独的预检或测试阶段。没有识别到任何屏幕时停止并如实告知用户；识别到的屏幕少于预期时按实际屏幕继续生成，并在最终交付时说明缺失编号。每屏提示词直接包含完整总体视觉基调和当前屏完整脚本，不得只传首行。

# 详情页图片执行说明（通用）

## 目标

将已确认的逐屏详情页脚本转换为一屏一图的图片任务。当前宿主如果提供图像工具，可以按屏执行；否则交付完整逐屏提示词和执行清单。

## 执行规则

- 每屏使用一条完整、连续的提示词，包含总体视觉基调、当前屏标题、正文、画面内容、设计目的和不可破坏的产品事实。
- 产品图是主体事实来源；参考图只按脚本中明确的构图、光线、色彩、字体气质或场景方式借鉴，不照搬品牌、文案或其他产品。
- 按屏幕顺序提交并记录每屏的素材映射、提示词版本、比例、模型、分辨率和输出路径。
- 宿主支持时可选择 GPT Image、Banana/Nano Banana 等图像模型；不要在技能文件中假设某个命令或服务一定存在。

## 验收

逐屏检查产品一致性、文字可读性、移动端安全区、信息密度、视觉连续性和事实准确性。宿主不支持生图时，明确标记为“待宿主执行”，不输出虚假的文件链接。

## 失败处理

- 宿主工具不可用、输入资产缺失或参数不受支持时，停止执行并明确列出缺口。
- 单屏失败时只修订该屏的提示词或资产映射，保留其他屏的顺序和版本记录。
- 未确认到真实输出文件前，标记为“待宿主执行”或“结果待确认”，不生成虚假链接。

## 最终交付

交付详情页脚本、逐屏完整提示词、产品与参考资产角色表、参数建议、输出路径（如有）和质检结果。
