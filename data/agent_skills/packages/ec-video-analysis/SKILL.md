# Ec-video-analysis

## 必填输入

开始分析前，必须要求用户提供一段视频作为核心输入。可以接受本地视频文件、可下载的视频 URL，或用户提供的视频附件/路径。

如果没有视频，不要凭描述生成完整分析报告；应先请用户提供视频。除非用户明确要求“仅提供假设分析框架”或“模板”，才可以不依赖视频输出方法论。

## 核心流程

1. 检查视频基础信息：时长、分辨率、画幅比例、帧率、是否有音频、编码格式、文件大小等。
2. 提取视频帧。尽量同时使用固定间隔采样和场景切换/关键时刻采样。
3. 对提取帧执行视觉识别，读取画面中的字幕、标题、标签、价格、行动号召、界面文字、品牌/产品文案等，不默认依赖额外文字识别引擎。
4. 基于镜头切换、运动密度、文字密度、视觉转场、片段时长，以及可用的音频/语速线索，分析节奏和韵律。
5. 基于人物表情、色彩、音乐/声音氛围、镜头运动、文案语气、视觉反差、故事节点、产品/用户语境，分析情绪和传播意图。
6. 生成一个详细的多维度分析文件。
7. 在最终回复中给出“报告总结”，并明确说明详细分析报告已生成到文件，同时提供分析文件路径。

需要完整分析框架和报告模板时，读取 `references/analysis-framework.md`。

## 视频帧提取指南

优先使用本地可用工具。若环境已安装 `ffprobe`/`ffmpeg`，优先用它们读取元数据和提取帧。

推荐采样策略：

- 做低频时间线采样，例如每秒 1 帧，或针对短视频均匀提取 12-30 张代表帧。
- 对剪辑密集的视频，额外使用 `ffmpeg` 场景切换阈值提取关键帧。
- 将帧保存到视频旁边或临时工作目录中，使用清晰命名的输出文件夹。
- 帧文件名应可排序，并尽量包含序号或时间戳。
- 如果视频很长，按章节或时间窗口分段采样，不要无限制提取过多帧。

可按需调整的示例命令：

```bash
ffprobe -v error -show_entries format=duration,size -show_streams -of json input.mp4
ffmpeg -i input.mp4 -vf fps=1 frames/frame_%06d.jpg
ffmpeg -i input.mp4 -vf "select='gt(scene,0.28)',showinfo" -vsync vfr scene/frame_%06d.jpg
```

如果没有 `ffmpeg`，可使用 Python/OpenCV、浏览器截图或其他可用的视频读取方式。报告中说明使用了哪种替代方案。

## 视觉识别指南

对代表性视频帧执行视觉识别，将画面中的文字和重要视觉信息整理成结构化证据。默认使用抽帧后的人工/模型视觉检查路径，不要求安装额外文字识别工具。

整理视觉识别结果时：

- 为每条识别文本保留时间戳或帧编号。
- 合并重复字幕、循环出现的贴片、常驻标题或水印。
- 区分品牌/产品文案、字幕、界面文字、价格/促销信息、行动号召。
- 标注低置信度识别、被遮挡文本、疑似误读文本。
- 多语言视频应保留原文；只有在有助于分析时再补充翻译。
- 同时记录非文字视觉证据，例如产品外观、人物表情、动作、场景、颜色、构图、镜头角度、焦点变化等。

## 报告要求

始终创建一个结构化分析文件。默认输出 Markdown 文件，文件名建议使用 `ec-video-analysis-report.md`、`<视频文件名>-analysis.md` 或带时间戳的等价名称。若用户指定 `.docx`、`.pdf`、`.xlsx` 等格式，按用户指定格式生成。

分析文件至少包含：

- 视频基础信息与采样方法。
- 执行摘要。
- 按时间段拆解的视频时间线。
- 视觉识别/画面文案识别结果。
- 节奏/韵律分析。
- 情绪/调性分析。
- 视觉与剪辑分析。
- 叙事结构或信息架构分析。
- 适用时分析受众、平台适配和转化意图。
- 优势、问题、风险和具体优化建议。
- 证据记录，引用时间戳、帧编号、视觉识别文案片段或可观察线索。

聊天最终回复必须包含“报告总结”，用较短篇幅概括核心结论、主要发现、关键问题和优先建议；同时明确说明“详细分析报告已生成到文件”，并给出分析文件路径。聊天总结不要替代文件中的完整详细报告。

不要把无法直接确认的信息说成事实，例如创作者真实意图、精确投放数据、真实受众画像等。此类内容必须标注为“推断”。

## 质量标准

报告要具体、可追溯、以证据为中心。好的 ec-video-analysis 应说明：发生了什么、发生在什么时候、为什么可能重要、应该如何优化。优先使用带时间戳的观察，而不是笼统形容词。
