# ec-mainimage-analysis

电商主图分析 skill。它可以单独使用，也可以作为 `ec-mainimage-planning` 的前置分析。

## 适合什么时候用

- 用户要先分析商品资料、评价、问大家、竞品图或参考图。
- 用户上传了 Excel/CSV 评价表、问大家表、SKU/参数表、PDF/Word/文本卖点文档或竞品卖点表。
- 用户上传自家现有5张主图或竞品5张主图，希望诊断或拆解套图打法。
- 用户想知道主图应该先打点击、信任、差异化、顾虑消除还是场景代入。
- 用户需要一份可交给后续策划、设计师或其他主图生成流程的分析报告。

## 用户该上传什么

最小可开始：产品图、标题/描述、现有主图、竞品图、评价截图、Excel/CSV、PDF/Word/文本文件之一即可。

推荐完整包：

| 类型 | 文件/内容 | 用途 |
|---|---|---|
| 产品事实 | 产品图、白底图、实拍图、包装图、SKU图 | 确认商品长什么样，避免后续生图跑偏 |
| 卖点事实 | 标题、参数表、卖点文档、SKU表、PDF/Word/文本文件 | 判断哪些文案能写，哪些要确认 |
| 用户反馈 | 评价/问大家截图、Excel/CSV 评价表 | 提炼痛点、顾虑、真实用户语言 |
| 主图现状 | 自家现有5张主图 | 找出当前主图的问题和改版机会 |
| 竞品参考 | 竞品5张主图、竞品截图、参考图 | 拆解竞品打法和视觉转译方向 |
| 约束偏好 | 平台、风格偏好、禁忌、目标人群 | 限定分析和后续策划方向 |

资料不完整也可以开始，报告会把缺失内容列入“用户补料需求”。

## 输出

默认保存到当前 agent 的工作目录下，使用相对路径：

`outputs/mainimage/<日期-商品简称>/主图分析.md`

如果系统或用户已经指定工作路径，必须尊重该路径。不要跳出当前工作目录，也不要写死 `/Users/...`、通用 Skill 宿主、宿主、桌面 App、cache、`Library/Application Support`、`.通用 Skill 宿主/workspace` 等机器专属绝对路径。

报告末尾包含“给主图策划的结构化交接”。这个交接可以给 `ec-mainimage-planning` 读取，也可以给人工策划使用。

## 下一步

- 如果报告显示资料足够：继续使用 `ec-mainimage-planning` 做5张主图策划。
- 如果缺产品事实锚点：先补产品图/白底图/实拍图。
- 如果缺痛点证据：补评价/问大家截图或 Excel/CSV。
- 如果想做差异化：补竞品5张主图或参考图。

## 和 planner 的关系

- 只想做资料诊断：单独使用本 skill。
- 想完整做五张主图：先用本 skill，再用 `ec-mainimage-planning`。
- 已经有清楚商品资料：可以跳过本 skill，直接使用 planner。

## 注意

如外部页面无法访问，不要编造页面内容；请让用户补充标题、卖点、参数表、SKU表或评价截图。

如用户上传 Excel/CSV，必须先读取文件内容，列出 sheet、表头、样例行和关键列，再提炼痛点、卖点和风险；不要只把表格文件名登记为资产。读取异常时先尝试常见编码、分隔符和 sheet 读取方式，可用 Python 作为 fallback，并记录尝试方式和失败原因。

如用户上传 PDF/Word/文本文件，必须先判断文档类型和可读性，记录页码/段落/表格、关键字段和实际使用内容；读取失败时记录失败原因，可继续低置信度分析，但不得把未读取内容写成证据。
