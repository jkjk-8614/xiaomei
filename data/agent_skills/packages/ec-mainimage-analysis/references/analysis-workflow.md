# 主图分析工作流

## 1. 输入资产抓取

先把用户给过的所有资料列出来，不要只看最后一条消息。

| 资产类型 | 识别方式 | 用途 |
|---|---|---|
| 产品图/白底图/商品实拍图 | 展示本商品外观、结构、颜色、材质、比例 | 产品事实锚点，后续生图优先带入 |
| 包装图/SKU图 | 展示包装、规格、口味、套装、品牌识别 | SKU/品牌锚点，不默认每张主图都出现 |
| 卖点/参数截图 | 展示参数、材质、功能、服务、卖点 | 事实证据和风险判断 |
| 评价/问大家截图或表格 | 展示真实反馈、疑问、差评、中评 | 用户痛点、购买顾虑、信任回应 |
| Excel/CSV表格 | 评价导出、问大家导出、SKU/参数表、竞品卖点表、用户调研表 | 强证据来源；必须先读取内容再分析 |
| PDF文档 | 商品资料、卖点文档、参数说明、品牌资料、竞品资料 | 先判断文本型还是扫描型，再提取可用证据 |
| Word/文本文件 | 商品文档、卖点文档、客服话术、参数说明、评价整理 | 提取标题、段落、表格和关键字段 |
| 自家现有主图套图 | 用户已有的1-5张商品主图，通常有图序 | 诊断当前主图任务分配、点击力、卖点重复、信息断层 |
| 竞品主图套图 | 竞品商品的1-5张主图，通常有图序 | 拆解竞品转化打法、信息密度、差异化机会，不作为本商品事实 |
| 竞品图 | 其他商品的主图/详情页/卖点表达 | 竞品对照，不作为本商品图 |
| 参考图 | 用户喜欢的风格、光影、构图、字体、场景 | 视觉转译，不照搬产品结构 |
| 口述要求 | 用户补充的平台、风格、禁忌、主推卖点 | 策略约束和待确认事实 |

如果用户只给了少量资料，也继续分析。少资料场景不要反复追问，先输出快速诊断，并把缺口按 P0/P1/P2 写入补料需求。

如用户已提供的外部页面或平台内容无法访问，不要猜页面内容。把该页面记入资产清单，状态写为“无法访问/待用户补截图”，再基于已给资料继续。

## 1.1 表格文件读取

遇到 `.xlsx`、`.xls`、`.csv`、`.tsv` 时，必须先打开并读取，不要只把文件名写进资产清单。

读取顺序：

1. 列出文件名、所有 sheet 名、每个 sheet 的大致行列数。
2. 读取每个相关 sheet 的表头和前几行样例，判断它是评价、问大家、SKU/参数、竞品、卖点还是订单/人群数据。
3. 找出可用于主图分析的关键列，例如评价内容、问题、回答、评分、规格、SKU、参数、价格、竞品卖点、用户标签、时间、频次。
4. 对评价/问大家类表格做高频归纳：痛点、好评原因、差评原因、反复提问、购买顾虑、真实用语。
5. 对 SKU/参数类表格提取可确认事实和不可确认项，不要把空列、公式错误或未证实字段写成卖点。
6. 在输入资产清单里写清“已读取哪些 sheet、用了哪些列、哪些 sheet 未使用以及原因”。

读取异常时按下面顺序降级：

1. `.xlsx/.xls` 优先使用可用的工作簿/表格读取工具读取 sheet，不要当普通文本处理。
2. `.csv/.tsv` 先判断编码和分隔符；编码按 `utf-8-sig -> utf-8 -> gb18030 -> gbk -> latin1` 尝试，分隔符按逗号、制表符、分号等常见形式尝试。
3. 常规工具仍失败时，可用 Python 作为 fallback，但不要把“用 Python”写成唯一方法。
4. 读取成功后必须记录读取证据：文件名、sheet 名、行列规模、表头、样例行、关键列、使用字段。
5. 读取失败时必须记录失败证据：已尝试方式、失败原因、影响哪些结论、建议用户重新上传或导出为 `.xlsx` / `utf-8-sig CSV`。

如果表格打不开、加密、路径不可访问或格式不支持，要明确写入风险/备注。不要因为表格读取失败就中断主图分析；可以基于已给资料继续，但要把涉及表格的结论标为低置信度或待补充。

## 1.2 PDF/Word/文本文件读取

遇到 `.pdf`、`.docx`、`.doc`、`.txt`、`.md` 等文档文件时，必须先判断文档类型和可读性，不要只登记文件名。

读取顺序：

1. 记录文件名、格式、文件角色推断：商品卖点、参数/SKU、品牌资料、评价整理、问大家整理、竞品资料、客服话术、待确认。
2. PDF：先判断是可复制文本 PDF 还是扫描图/图片型 PDF。
   - 可复制文本 PDF：提取页数、页码、标题、表格、参数、卖点、关键段落。
   - 扫描图/图片型 PDF：尝试可用 OCR 或转图片识别；失败时要求用户补文字版、截图或重新导出。
3. Word：
   - `.docx` 优先按结构读取标题、段落、表格、图片说明。
   - `.doc` 兼容性较差；读取失败时建议用户转成 `.docx` 或 PDF。
4. 纯文本/Markdown：读取标题、列表、表格、关键字段；如果乱码，按常见编码降级或要求用户重新导出。
5. 从文档中提取可用于主图分析的证据：商品事实、卖点、参数、服务、用户痛点、竞品表达、禁用/慎用表达。
6. 在输入资产清单里写清“读取了哪些页码/段落/表格、用了哪些字段、哪些内容未使用以及原因”。

读取失败降级：

- 不要中断主图分析，也不要假装已使用文档内容。
- 必须记录读取方式、失败原因、影响哪些结论、建议用户补什么格式。
- 可基于已给图片、口述、评价或其他资料继续分析，但依赖文档的事实结论标为“低置信度/待确认”。

## 1.3 主图套图读取

用户上传约5张主图时，先判断它们是“自家现有主图”还是“竞品主图”。如果用户没说清楚，在报告里标为“待确认”，但仍可先分析套图结构。

按图序逐张读取：

1. 记录图序：主图1、主图2、主图3、主图4、主图5；如果文件名无序，按用户上传顺序或文件名推断，并标注推断。
2. 识别每张图任务：点击吸引、产品确认、卖点证明、顾虑回应、场景代入、规格/SKU、信任背书、活动促销。
3. 记录画面结构：产品占比、背景、道具/人物、场景、文字位置、标题/标签层级、信息密度。
4. 评估套图关系：是否有递进、是否重复卖点、是否缺少关键顾虑回应、是否首图点击力弱、是否后几张信息断层。
5. 区分用途：自家主图可诊断改版问题；竞品主图只能拆解打法，不能把竞品商品、认证、品牌、结构当成本商品事实。
6. 输出可转译方向：借鉴图序分工、信息层级、构图节奏和小图可读性，不照搬竞品文案和视觉资产。

## 2. 证据等级

把结论分为五类：

- A：图片可见或页面明确写出，可作为主图事实。
- B：用户明确口述，可作为策划依据，但强背书需用户确认。
- C：评价/问大家高频反馈，可作为痛点/机会。
- D：竞品/品类常识推断，只能作为策略方向。
- E：缺证据或高风险，不得直接写成文案。

## 3. 人群显性/隐性需求分析

先用淘宝/天猫商家的视角回答：这个产品卖给谁，用户显性想买什么，隐性在意什么，第一眼为什么愿意点开。

分析时按下面顺序：

1. 如果用户明确给了消费人群，以用户人群为准；如果给了多个人群，分别拆开分析，不要混成一个泛泛人群。
2. 如果用户没给人群，根据产品图、标题、卖点、价格感、平台、评价/问大家、参考图和竞品图推断 1-3 类主要人群，并标注“推断/低置信度”。
3. 每类人群都要区分显性需求和隐性需求：
   - 显性需求：用户会直接说出来或搜索的需求，如尺寸、功能、材质、安装、适配、风格、价格、送礼。
   - 隐性需求：用户不一定明说但影响点击和下单的心理，如身份感、审美认同、安心感、怕踩雷、怕廉价、怕不搭、怕麻烦。
4. 把人群需求转成主图语言：第一眼点击触发点、画面应该先证明什么、文案应该回应什么。
5. 不编造不存在的强事实；需求可以是策略推断，但卖点事实必须回到证据边界。

输出表格字段固定为：

| 人群 | 显性需求 | 隐性需求 | 购买顾虑 | 第一眼点击触发点 | 主图回应方向 | 证据/置信度 |
|---|---|---|---|---|---|---|

## 4. 竞品/参考图高点击反推

如果用户给了竞品主图、参考图、竞品截图、拼图大图或平台搜索页截图，先从点击率和主图转化角度提炼共性，不要逐张打分，不要逐张点评。

分析目标不是评价哪张图好看，而是反推这批图为什么容易被目标用户看到、理解、点开或继续了解。必须结合前一步的人群显性需求和隐性需求。

优先覆盖这些维度；资料不足时保留最相关维度即可：

- 第一眼吸引点
- 品类识别
- 视觉抓力
- 核心卖点
- 场景/生活方式联想
- 尺寸感/使用感
- 材质/工艺感
- 差异化
- 审美记忆点
- 文案效率
- 信任感
- 点击诱因
- 情绪价值/购买理由
- 可迁移方法

统一输出表格字段：

| 维度 | 参考/竞品图中的典型表现 | 用户会感知到什么 | 为什么容易被吸引/点开 | 可借鉴的点 | 可优化的表达方向 |
|---|---|---|---|---|---|

注意：

- 标品和非标品暂不分流，统一按主图点击和转化逻辑分析。
- 竞品图只能借鉴打法、信息层级、视觉结构和表达方法，不把竞品产品、品牌、认证、参数当成本商品事实。
- 参考图不需要一刀切排除人物、服装、道具、背景；要按后续策划目的写清“可借鉴什么”和“哪些元素需改写或不要自动带入”。
- 如果图片只有风格参考价值，也要说清它不能证明本商品卖点。

## 5. 分析顺序

按下面顺序输出，不新增置顶总结段：

1. 用户痛点/机会。
2. 竞品/参考图高点击反推。
3. 视觉转译与使用边界。
4. 关键洞察排序。
5. 人群显性/隐性需求。
6. 主图机会优先级。
7. 卖点分层。
8. 商品事实与证据边界。
9. 文案风险。
10. 输入资产清单。
11. 用户补料需求。
12. 下一步建议。
13. 给主图策划的结构化交接。

## 5.1 排序规则

- 所有表格默认按重要性排序，不按资料出现顺序排序。
- 痛点/机会按“影响转化程度 + 证据强度 + 是否能被主图回应”排序。
- 卖点按“点击价值、转化价值、信任价值、差异化价值”排序。
- 风险按“法务/平台风险、事实不确定性、生成误导风险”排序。
- 输入资产按“产品事实锚点、强证据、视觉参考、辅助资料、待确认”排序。
- 人群需求按“人群优先级 + 需求强度 + 主图可回应程度”排序。
- 高点击反推按“对点击影响 + 对本商品可迁移程度 + 风险低”排序。

## 6. 主图机会优先级

分析结束前判断后续主图最该优先解决哪类问题：

| 机会类型 | 适用信号 | 后续主图方向 |
|---|---|---|
| 点击 | 产品外观强、价格/利益点强、竞品同质化严重 | 主图1强化第一眼差异和主卖点 |
| 信任 | 用户担心质量、材质、服务、真假、安装、售后 | 增加证据、细节、包装、服务承诺，但不写虚假背书 |
| 差异化 | 同类商品多，卖点容易撞车 | 用对比、结构细节、场景差别表达 |
| 顾虑消除 | 评价/问大家集中在尺寸、使用、安装、耐用、适配 | 让一张或多张主图专门回答顾虑 |
| 场景代入 | 用户需要想象使用效果、搭配、送礼、家居/穿搭场景 | 用场景图强化结果感 |

## 6.1 主图套图诊断维度

| 维度 | 自家现有主图 | 竞品主图 |
|---|---|---|
| 图序任务 | 判断每张是否承担明确转化任务 | 拆解竞品如何安排点击、信任、顾虑和收口 |
| 点击力 | 看主图1是否清楚、有差异、有停留理由 | 看竞品首图用什么利益点或视觉钩子 |
| 信息递进 | 看后4张是否逐层补证据，而不是重复 | 看竞品是否有完整转化漏斗 |
| 文案层级 | 看标题、标签、利益点是否可读 | 借鉴层级，不复制文案 |
| 风险 | 找出虚假/过度承诺/看不清/跑题 | 不把竞品事实当成本商品事实 |

## 7. 交接原则

- `asset_manifest` 必须标明产品图、白底图或商品实拍图是否存在。
- `audience_needs` 必须把显性需求、隐性需求、购买顾虑和点击触发点交给 planner。
- `click_reverse_engineering` 必须保留竞品/参考图高点击共性和可迁移方法，方便 planner 生成主图内容策略矩阵。
- `risk_boundary` 必须列出不能写或需要确认的表达。
- `reference_translation` 只写可借鉴的视觉语言，不把参考图产品当成本商品。
- 如输入包含主图套图，`reference_translation` 要写清可借鉴的套图结构和不可照搬的竞品元素。
- 结构化交接放在 `主图分析.md` 末尾，方便主图策划读取。
- `planning_notes.priority_tasks` 写清后续五图优先解决的主图任务，方便 planner 不平均分配卖点。
