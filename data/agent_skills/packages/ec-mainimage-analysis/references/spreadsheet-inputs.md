# 表格输入读取规则

Excel/CSV 表格常常是评价、问大家、SKU 参数、竞品卖点和用户调研的来源。处理这类文件时，重点不是复述整张表，而是把表格变成可用于主图决策的证据。

## 必须先读取

如果用户上传 `.xlsx`、`.xls`、`.csv`、`.tsv`，先打开文件并读取结构：

- 文件名
- sheet 名
- 每个 sheet 的大致行列数
- 表头
- 前几行样例
- 关键列

不要只写“用户上传了 Excel 表格”。如果还没有读取内容，不要基于表格做结论。

## 读取失败降级

表格读取失败时不要中断，也不要假装已经使用数据。按下面顺序处理：

1. `.xlsx/.xls`：优先用可用的工作簿/表格读取工具读取 sheet；这类文件不是纯文本，不要先按文本编码猜。
2. `.csv/.tsv`：先判断编码和分隔符。编码按 `utf-8-sig -> utf-8 -> gb18030 -> gbk -> latin1` 依次尝试；分隔符按逗号、制表符、分号等常见形式尝试。
3. 常规读取仍失败时，可以用 Python 作为 fallback，但不要把 Python 写成唯一或默认强制方案。
4. 读取成功后，在报告里记录读取证据：文件名、sheet 名、行列数、表头、样例行、关键列、实际使用字段。
5. 读取失败后，在报告里记录失败证据：已尝试方式、失败原因、影响哪些结论、建议用户重新上传或导出为 `.xlsx` / `utf-8-sig CSV`。

如果表格未成功读取，可以继续做低置信度分析，但凡依赖表格的痛点、卖点、评价或参数结论都必须标为“未验证/待补充”。

## 按表格类型提炼

| 表格类型 | 识别线索 | 提炼重点 |
|---|---|---|
| 评价导出 | 评价内容、评分、追评、规格、时间 | 高频好评、差评、中评、真实用语、顾虑 |
| 问大家导出 | 问题、回答、用户提问 | 购买前疑问、决策阻碍、必须回应的问题 |
| SKU/参数表 | 型号、规格、颜色、尺寸、材质、价格 | 可确认事实、SKU差异、不可写死项 |
| 竞品卖点表 | 竞品名、主图文案、价格、卖点 | 竞品同质点、可差异化方向、慎用表达 |
| 用户调研表 | 人群、场景、需求、顾虑 | 人群标签、使用场景、情绪卖点 |

## 输出到分析报告

在 `主图分析.md` 里必须体现：

- 输入资产清单：表格文件名、sheet 名、读取状态、关键列。
- 关键洞察：从表格归纳出的高频痛点和卖点。
- 证据边界：哪些来自表格，可信度如何。
- 用户补料需求：哪些列缺失、哪些字段需要用户确认。
- 结构化交接：把表格提炼出的痛点、卖点、风险写入 `pain_points`、`selling_points`、`risk_boundary`。

## 不要这样做

- 不要只登记文件名。
- 不要只看第一个 sheet。
- 不要把所有行原样贴进报告。
- 不要把低频孤例当成核心痛点。
- 不要把表格里未证实的功效、认证、排名直接写成主图文案。
