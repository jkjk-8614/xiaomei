# 示例

用户：

> 先做主图分析。我上传了产品图、竞品图和评价截图。

输出：

- 保存 `主图分析.md`
- 文件里先列输入资产清单，再写商品事实、用户痛点、卖点证据、文案风险。
- 文件末尾放“给主图策划的结构化交接”，不单独输出 JSON 文件。

## 示例 2：资料很少时

用户：

> 只有这张产品实拍图，先看这个产品主图应该怎么打。

输出：

- 仍保存 `主图分析.md`，不要因缺详情页/评价而中断。
- 标注这是低置信度快速诊断。
- 把缺少的详情页卖点、评价/问大家、白底图列为补料需求。

## 示例 3：链接无法访问时

用户：

> 帮我分析这个淘宝链接的主图机会。

输出：

- 如果链接无法访问，不编造商品详情。
- 在资产清单中记录链接状态。
- 基于用户已提供内容继续分析，并提示补充商品标题、卖点、参数表、SKU表或评价截图。

## 示例 4：上传 Excel 评价表

用户：

> 我上传了产品图和评价导出的 Excel，先做主图分析。

输出：

- 先读取 Excel：列出 sheet 名、行列规模、表头、样例行和关键列。
- 如读取异常，尝试常见编码/分隔符/sheet 读取方式；可用 Python 作为 fallback，并记录尝试方式与失败原因。
- 从评价内容、评分、规格、追评等列归纳高频痛点、好评原因和差评风险。
- 在输入资产清单里写明 Excel 已读取哪些 sheet，哪些列用于分析。
- 不要只写“用户上传了 Excel”就开始分析。

## 示例 5：上传 PDF/Word 卖点文档

用户：

> 我上传了产品卖点 PDF 和一份 Word 参数文档，先帮我分析主图方向。

输出：

- 先判断 PDF 是文本型还是扫描型，记录页数、可读取页码、标题、表格和关键段落。
- 先读取 Word 的标题、段落、表格和关键字段；如果是 `.doc` 读取失败，建议用户转为 `.docx` 或 PDF。
- 在输入资产清单里写明实际使用了哪些页码、段落、表格和字段。
- 读取失败时记录失败原因，继续基于其他资料低置信度分析，不把未读取内容写成证据。

## 示例 6：上传5张主图

用户：

> 我上传了竞品的5张主图，帮我分析它这套图怎么打。

输出：

- 先判断这是竞品主图套图，不作为本商品产品事实。
- 按主图1-5逐张分析任务、文案、产品占比、信息层级和优缺点。
- 总结竞品套图的转化递进、重复浪费、顾虑回应和可转译方向。
- 明确不可照搬的竞品品牌、认证、商品结构和文案。
