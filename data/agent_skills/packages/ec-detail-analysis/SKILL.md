# 淘宝详情页诊断

## 目的
分析淘宝/天猫商品详情页图片、长图或截图。默认站在商家学习与迁移的角度，拆解行业 Top 或竞品页面为什么有效、哪些打法值得借鉴、如何迁移到自己的产品详情页。分析阶段不要求用户上传自家产品白底图；只上传参考详情页也能完整输出分析报告。只有用户明确说明这是自家页面且要找问题时，才进入自家诊断模式。

## 模式判断
- 竞品拆解模式：当用户提到“竞品”“top”“行业top”“行业 Top”“标杆”“对手”“参考这个页面”“学习这个页面”“拆这个页面”时使用。
- 自家诊断模式：当用户提到“我的详情页”“自家页面”“我们页面”“帮我优化”“转化差”“找问题”“哪里不行”时使用。
- 如果用户没有说明，优先按竞品拆解模式输出，因为商家通常是拿优秀页面来学习打法。
- 竞品拆解不要只靠用户说“同类”或“跨行业”判断迁移方式；必须先识别参考页类目，再看用户是否提供我方产品信息，最后决定迁移深度。

## 迁移深度判断
- 先根据图片中的商品、文案、使用场景和页面模块，判断参考页大致类目；看不清时标注“不确定”。
- 再判断用户是否提供我方产品信息，包括产品图、产品名称、类目、目标人群、卖点，或“我卖什么”。
- 如果没有我方产品信息，不强行判断同类、近邻或跨行业；输出“通用打法型策划摘要”和“需要结合我方产品再翻译的部分”，不要直接写成某个产品的生成方案。
- 如果有我方产品信息，再判断参考页和我方产品的关系：同类竞品、近邻类目、跨行业 Top、自家页面。
- 同类竞品：可以借鉴卖点顺序、模块结构、场景表达、证据逻辑。
- 近邻类目：借鉴用户心智、页面节奏和表达方法，卖点、人群和场景必须重新翻译。
- 跨行业 Top：只借鉴结构、节奏、画面组织、欲望塑造方式和证据安排方法，不照搬具体卖点、行业术语、功效、素材和背书。

## 两阶段联动
- 第一阶段是分析：只拆参考页或自家页，保存报告，输出 `生成用策划摘要`；不要求用户提供自家产品图。
- 第二阶段是生成：只有用户回复需要继续生成时，才由 `$ec-detail-planning` 要求产品图和产品名称，并把策划摘要翻译成自家详情页脚本。
- 如果用户只单独使用分析 skill，不要因为缺少自家产品图而追问或降低报告质量；按通用打法型报告输出。
- 如果用户分析后回复需要但没有提供产品图或产品名称，只提示这些信息在生成阶段补充，不要生成脚本。

## 输入处理
- 优先读取用户提供的图片顺序，先判断是否为首屏、详情中段、证明模块、场景模块或收尾模块。
- 如果只有图片，明确写出“基于图片可见内容判断”。
- 如果用户同时给出商品名、类目、价格、链接或竞品背景，用这些信息校准页面定位和分析重点。
- 不要求用户在分析阶段上传自家产品白底图；产品图是生成 skill 的必填项，不是分析 skill 的必填项。
- 如果信息缺失，只在相关判断里标注不确定，不单独输出“需要补充的信息”维度。

## 竞品拆解流程
1. 先一句话判断这个竞品页面主要靠什么打动用户。
2. 先写参考页类目判断，再判断是否具备我方产品信息。
3. 拆它做对了什么：首屏心智、主卖点压缩、场景欲望、证据安排、图文节奏、成交推进。
4. 提炼值得学习的 Top 5 做法，重点说明背后的转化逻辑。
5. 按迁移深度输出：哪些可以迁移、哪些需要结合我方产品再翻译、哪些不能直接照抄。
6. 只在最后简短写“不建议照抄的地方”，不要把竞品分析写成挑错报告。

## 自家诊断流程
1. 先一句话判断自家页面当前主要卡在认知、欲望、信任、节奏还是成交推进。
2. 按参考框架检查首屏钩子、商品认知、核心卖点、欲望塑造、信任与证据、场景代入、视觉节奏和成交推进。
3. 将问题按对转化的影响排序，指出会削弱购买欲、主卖点和页面节奏的问题。
4. 对每个问题给出具体改版方向：该前置什么、弱化什么、换什么顺序、哪类画面或文案要加强。

## 详情页职责边界
- 不默认分析价格。价格、券、活动钩子主要属于主图、搜索结果页、购买组件或活动页职责；除非用户明确要求，详情页分析不把价格缺失列为高优先级问题。
- 不默认深挖 SKU。SKU 面板负责规格选择；详情页只在规格差异会影响主卖点理解时简单提及。
- 不默认把窗帘测量、褶皱倍数、复杂定制细节列为高优先级问题；这些通常属于客服承接或购买咨询环节。
- 不默认强调评价与问大家；它们只作为辅助信任素材，在页面主动展示或用户要求时分析。
- 不默认把合规风险放进 Top 5；只有明显会影响投放、审核、处罚或下架时才提醒。
- 不强制要求 Before/After 图；对比图只在类目、卖点或页面表达确实需要时建议。

## 输出格式
竞品拆解模式默认用中文输出：
- 一句话结论
- 它主要靠什么打动用户
- 值得学习的 Top 5 做法
- 分维度拆解
- 参考页类目判断
- 它的通用打法是什么
- 迁移到我方详情页的做法
- 哪些可以迁移
- 哪些需要结合我方产品再翻译
- 不建议照抄的地方
- 生成用策划摘要

自家诊断模式默认用中文输出：
- 一句话结论
- 转化判断
- 主要问题 Top 5
- 分维度诊断
- 优先改版建议
- 生成用策划摘要

## 写作规则
- 先给结论，再给分析。
- 竞品页不要默认挑问题；分析目标是提炼打法，不是评价竞品好坏。
- 对竞品的问题只在“可避坑”或“不建议照抄的地方”里简短提。
- 从商家转化视角判断页面，不要把分析写成平台风控报告。
- 用具体可见事实，少用抽象评价词。
- 不要编造销量、评价、资质、活动价或页面外信息。
- 对看不清或无法确认的内容直接在对应判断里标注不确定。
- 食品、个护等类目的健康心智表达，优先判断其卖点心智和购买欲；只有明显过界时低频提醒合规。
- 避免机械建议“补价格、补 SKU、补问大家、补 Before/After、补客服测量信息”。


## 报告保存
- 每次完成详情页分析后，将同一份分析内容保存为 Markdown 报告。
- 默认保存目录为当前工作区下的 `reports/ec-detail-analysis`；如果用户指定其他目录，按用户指定目录保存；如果目录不存在，先创建目录。
- 文件名使用 `yyyyMMdd-HHmmss-详情页分析.md`，如果用户提供商品名或品牌名，可追加简短中文标识。
- Markdown 报告正文应包含本次完整分析内容，不要只保存摘要。
- 在最终回复末尾告知用户报告保存的完整绝对路径；该路径必须按本次运行环境动态解析，不要使用写死的固定路径。回复格式示例：`报告已保存：<当前工作区绝对路径>/reports/ec-detail-analysis/yyyyMMdd-HHmmss-详情页分析.md`。

## 生成联动
- 每次完成分析后，必须在分析正文末尾输出 `## 生成用策划摘要`，用于联动 `$ec-detail-planning`。
- `生成用策划摘要` 必须面向“我方详情页生成”，不是竞品复述；要把竞品打法转译为可迁移策略。没有我方产品信息时，只输出通用打法和待翻译部分，不要硬套具体类目卖点。
- `生成用策划摘要` 固定包含：
  - `策划摘要类型：`
  - `参考页面类型：`
  - `参考页类目判断：`
  - `我方产品信息：`
  - `类目适配说明：`
  - `生成阶段需补充：`
  - `产品定位建议：`
  - `目标人群：`
  - `核心购买动机：`
  - `主卖点：`
  - `辅助卖点：`
  - `首屏打法：`
  - `视觉风格：`
  - `画面语言：`
  - `证据逻辑：`
  - `建议详情页结构：`
  - `不建议照抄：`
  - `生成备注：`
- 保存 Markdown 报告时，报告正文也必须包含完整 `生成用策划摘要`。
- 如果用户未提供我方产品信息，`策划摘要类型` 写 `通用打法型`，`我方产品信息` 写 `未提供`，`生成阶段需补充` 写 `产品图、产品名称、我方类目/核心卖点（可选）`；`产品定位建议`、`目标人群`、`主卖点` 可以写 `待生成阶段结合产品图和产品名翻译`，不要硬套参考页类目。
- 如果用户已提供我方产品信息并完成类目适配，`策划摘要类型` 写 `类目翻译型`；如果是自家页面诊断，写 `自家改版型`。
- 分析完成并告知报告路径后，追加一句固定追问：`需要我基于这份生成用策划摘要继续策划生成你自己的详情页吗？如果需要，请回复“需要”，并在生成阶段提供产品图和产品名称。`
- 如果用户回复“需要/继续/生成/策划”并提供产品图和产品名称，则继续使用 `$ec-detail-planning`；把刚才报告路径或 `生成用策划摘要` 作为该 skill 的 `参考分析报告` / `竞品分析摘要` 输入。
- 如果用户回复需要但缺少产品图或产品名称，先让用户补充缺失项，不要生成脚本。
